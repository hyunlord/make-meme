## 0. 목표 — 새로운 조건 모듈을 추가하기 전, 입력 충돌 하나를 분리한다

최종 연구 목표는 다음과 같다.

원본 영상 + 편집 지시 + 선택적 참조 이미지
→ 소수의 편집 앵커
→ 객체별 동작·외형 연결
→ 로컬 영상 생성
→ 대상 외형·원본 동작·보호 장면을 함께 유지하는 영상 편집

C-002의 동적 윤곽은 개의 거친 접근 진행을 개선했다.
C-003의 내부 구조선 추가는 명확한 추가 이득을 입증하지 못했다.

두 실험에는 동일한 종료 앵커가 사용됐다.
이 앵커는 원본 마지막 프레임의 보행 상태보다
몸과 머리가 낮고 웅크린 형태로 관측됐다.

이번 질문:

“종료 앵커를 원본 마지막 시점의 자세에 더 맞게 교정하면,
다른 조건을 유지한 상태에서 종료부 또는 중간 동작이 개선되는가?”

이번은 입력 충돌의 영향을 분리하는 한정 비교다.
새 영상 아키텍처·관절 대응·학습 방법을 검증하는 실험이 아니다.

종료 앵커 교정을 끝없이 반복하지 않는다.
한 번의 앵커 생성과 한 번의 정상 영상 생성으로 비교하고 종료한다.

A/B의 실패·보류, C-001 PARTIAL,
C-002의 차량 TRADE_OFF·개 COARSE_CONTROL_ONLY,
C-003 NO_ESTABLISHED_GAIN을 그대로 보존한다.
B-034 복구는 하지 않는다.

## 2. 고정 입력과 비교 구조

기존 개 case_nonrigid만 사용한다.

- source: 기존 dog 33프레임
- target reference: C-001에서 사용한 dog-gooses 참조
- 시작 앵커: C-001의 실제 imagegen 시작 이미지
- 기존 종료 앵커: C-001의 실제 imagegen 종료 이미지
- 동적 윤곽: C-002의 기존 LAYOUT_MOV 조건
- 기준 영상: C-002 개 LAYOUT_MOV의 raw/PNG/MP4

정확한 원본 frame ID와 파일은 기존 manifest를 따른다.
local0~32는 클립 내부 인덱스다.
다른 원본 프레임이나 더 좋은 참조로 바꾸지 않는다.

비교:

BASE_END:
기존 시작 앵커
+ 기존 종료 앵커
+ 기존 동적 윤곽
→ C-002 MOV 결과 재사용

CORRECTED_END:
같은 시작 앵커
+ 이번에 교정한 종료 앵커
+ 같은 동적 윤곽
→ 신규 영상1개

C-003 DYNAMIC/HOLD 내부 구조선은 둘 다 사용하지 않는다.
기준 영상을 다시 생성하지 않는다.


## 3. 생성 전에 교정 목표를 실제 이미지로 고정

원본 마지막 프레임, 기존 종료 앵커, 시작 앵커,
target reference를 실제로 열어 비교한다.

사전 기록은 짧게 작성하되 다음을 구분한다.

1. 원본 마지막 프레임에서 직접 보이는 자세
2. 기존 종료 앵커와 충돌하는 부분
3. 교정 후에도 유지해야 할 target 외형
4. 가림·blur 때문에 판단할 수 없는 부분

특히 다음을 확인한다.
- 몸통의 높이와 기울기
- 머리의 몸통 대비 위치·방향
- 보이는 앞발의 전후 배치
- 다리 겹침과 가림
- 화면 내 대상 위치·크기
- 카메라와 주변 장면

“개를 똑바로 서 있게 만든다”라는 일반적인 목표로 바꾸지 마.
원본에서도 머리가 낮으면 그 상태를 유지해야 한다.
교정 목표는 추상적인 기립 자세가 아니라
실제 source local32의 관측 가능한 상태다.

화면 좌우를 동물의 해부학적 좌우로 단정하지 않는다.
가려진 발·관절을 보이게 만들거나 숨은 접촉을 정답으로 지정하지 않는다.

원본과 새 개체의 체형이 다르므로
실루엣의 완전한 픽셀 일치를 요구하지 않는다.
전체 행동 상태와 보이는 부위 관계를 우선한다.

이 관측표와 앵커 수용 기준은 imagegen 호출 전에 기록한다.
이미지와 영상 결과를 본 뒤 좋은 항목만 평가 기준으로 고르지 않는다.


## 4. 종료 앵커 생성 — 실제 native imagegen 1회

C-001에서 사용한 Codex Astra의 native imagegen 경로를 사용한다.
이번 assistant가 이미지를 생성한 것으로 가정하지 않는다.
실행 담당자가 실제 도구를 호출하고 결과를 등록해야 한다.

실제 입력 이미지는 다음 세 장이다.

Image 1 — 편집할 바탕:
기존 좌표계의 원본 마지막 프레임 source local32.
자세·카메라·배치·배경의 기준이다.

Image 2 — 외형 참조:
C-001에서 사용한 target reference.
목표 개체의 털색·무늬·얼굴·체형 특징 기준이다.

Image 3 — 외형 일관성 참조:
기존 시작 앵커.
영상 시작과 끝에서 같은 target 디자인을 유지하기 위한 기준이다.
이 이미지의 자세와 배경을 마지막 프레임에 복사하지 않는다.

기존 잘못된 종료 앵커는 비교 자료로 보존하되,
기본 생성 입력에는 넣지 않는다.
웅크린 상태가 다시 복사되는 것을 줄이기 위한 선택이다.

실제 도구가 읽을 수 있는 입력으로 파일을 전달한다.
경로를 프롬프트에 적기만 하고 이미지 입력을 생략하지 않는다.
입력 순서·파일 hash·프롬프트·실제 도구 결과의 계보를 기록한다.

실제 native imagegen이 없다면 IMAGEGEN_UNAVAILABLE로 보고한다.
API·다른 유료 서비스·Qwen 등으로 조용히 바꾸지 않는다.

이번 호출은1회, 후보1장이다.
다른 seed나 prompt로 품질 재시도하지 않는다.
여러 후보를 만들어 가장 좋은 결과를 고르지 않는다.

도구가 실제 실행되기 전의 파일 업로드·참조 오류는
같은 작업 안에서 고칠 수 있다.
실제 생성 호출 여부를 확인해 장부에 기록하고,
중복 생성 가능성이 있으면 자동 반복하지 않는다.

도구가 반환한 실제 모델 식별자·청구 정보가 있으면 기록한다.
노출되지 않은 내부 모델명·비용은 UNKNOWN이다.

---
첫 번째 이미지를 편집해 주세요.

첫 번째 이미지에 있는 주대상 개를,
두 번째 참조 이미지와 세 번째 시작 앵커에 나타난
검정·흰색 대상 개의 외형으로 교체해 주세요.

정보의 역할은 다음과 같습니다.
- 첫 번째 이미지: 마지막 순간의 자세, 방향, 위치, 카메라, 배경.
- 두 번째 이미지: 목표 개체의 외형과 무늬.
- 세 번째 이미지: 영상 시작과 끝에서 유지할 같은 개체의 디자인.
두 번째와 세 번째 이미지의 자세나 배경은 복사하지 마세요.

첫 번째 이미지의 실제 순간을 유지해 주세요.
몸통의 높이와 기울기, 머리와 몸의 상대 위치,
보이는 앞발의 전후 배치와 겹침을 관측 가능한 범위에서 유지해 주세요.

원본에서 고개가 낮다면 그대로 유지하되,
원본에 없는 웅크림·앉기·눕기 자세를 만들지 마세요.
가려진 다리를 억지로 드러내거나 보이지 않는 관절을 강조하지 마세요.

목표 개체의 자연스러운 체형 차이는 허용하지만,
행동의 단계나 대상의 화면 내 위치가 달라지면 안 됩니다.

울타리, 수풀, 잔디의 큰 구조와 주변 객체,
카메라 시점, 장면 배치는 첫 번째 이미지를 유지해 주세요.

단일 장면의 이미지 한 장을 출력해 주세요.

## 6. 이미지 전처리와 영상 단계 진입 판단

imagegen 원출력을 수정하지 않은 파일로 보존한다.

모델용 앵커는 C-001의 공통 좌표·색상 처리 규칙을 재사용한다.
- 최종 RGB832×480
- 기존 canvas/aspect-fit/resize 규약
- 원출력과 실제 모델 입력을 모두 보존

가능한 도구 옵션 안에서 source와 같은 종횡비를 요청한다.
지원하지 않는 출력 크기를 지원한다고 가정하지 않는다.

자세를 고치기 위한 비선형 warp·사지 이동·임의 crop·
발 위치 수동 수정·배경 덮어붙이기를 하지 않는다.
표준 크기 변환을 자세 보정으로 위장하지 않는다.

새 앵커를 기존 시작·기존 종료·source32·reference와 함께 확인한다.

영상 입력에 적합한 조건:
- 사전에 기록한 큰 자세 충돌이 실제로 줄어듦.
- 검정/흰 외형과 시작 앵커의 대상 디자인이 대체로 유지됨.
- 대상이 하나이고 큰 신체 손상·중복이 없음.
- 카메라·배치·보호 장면에 큰 변화가 없음.

완벽한 발 접촉·미세 털·모든 픽셀의 배경 일치를 요구하지 않는다.
작은 불확실성은 기록하고 진행할 수 있다.

판정:
SUITABLE_FOR_COMPARISON
- 주요 충돌이 줄었고 큰 회귀가 없어 영상 비교 진행.

PARTIAL_BUT_USABLE
- 자세 방향의 개선은 확인되지만 일부 미세 오차·배경 차이가 있음.
- 차이와 제한을 명시하고 영상 비교 진행.

ANCHOR_UNSUITABLE
- 기존 웅크림이 유지되거나 큰 외형·배치 손상이 생김.
- 영상 생성은 생략하고 이번 앵커 실패를 보존.
- 두 번째 imagegen을 자동 실행하지 않음.

판단은 새 영상 생성 전에 고정한다.
이 판정에 영상 결과를 사용하지 않는다.
앵커가 부적합한 경우 영상 단계의 효과를 FAIL로 세지 않는다.

생성 전 검사:
- 입력 RGB33장 중 바뀐 것은 local32뿐인가?
- local0과 중간1..31이 기존 조건과 같은가?
- G33장과 실제 압축 마스크가 같은가?
- prompt·negative·모델 설정·seed가 같은가?
- 새 종료 앵커가 실제 config에 연결됐는가?

단순 파일 경로만 확인하지 말고 실제 조건 픽셀 hash를 비교한다.

기존 최초 model_fn 관측 hook을 재사용한다.
추가 관측용 forward는 하지 않는다.

확인할 것:
- 실제 초기 noisy latent hash
- VACE context shape/dtype/finite/hash
- mask64채널 hash
- effective vace_scale

초기 noise는 C-002 기록과 비교한다.
기존 기록:
cf71cc3501ff09f876a384a20e9aedea41fb7eaaf956e5da52e8f777c9fbf9ba

기대 shape:
noise [1,16,9,60,104]
context [1,96,9,60,104]

C-002와 실제 noise가 다르면 동일하다고 가정하지 않는다.
파일·dtype·RNG 경로를 확인하고 비교의 한계를 명시한다.
noise 일치만을 위한 추가 품질 생성은 하지 않는다.

논리 입력상:
- inactive RGB는 마지막 앵커 부분만 변경.
- reactive RGB와 G는 유지.

시간 VAE가 주변 프레임을 함께 처리하므로
“마지막 앵커만 바뀌었으니 latent의 마지막 위치 하나만 바뀌어야 한다”
같은 잘못된 assertion을 넣지 않는다.

모델 내부 특징이나 출력의 다른 시점까지 달라질 수 있다.
변경 범위를 입력 단계와 모델 내부 단계에서 구분한다.

기존 텐서를 여러 번 대량 저장하거나
전체 가중치를 반복 해시하는 감사는 하지 않는다.


## 9. 실행 예산과 오류 처리

정상 실행 예산:
- native imagegen:1회, 후보1장
- 새 영상 sampler:1회
- 정상 완료 시50step·100 model_fn call
- 해당 final latent decode:1회

imagegen 품질 재시도0회.
새 seed·prompt·구조·모델을 시험하는 영상 재생성0회.

기계적 실행 오류:
- GPU 모델 적재 전의 경로·인자·import·설정 오류는
  같은 의뢰 안에서 수정하고 필요한 CPU 검사를 다시 할 수 있다.
- 새 연구 번호나 별도 운영 연구를 만들지 않는다.
- 기존 정상 결과를 이미 얻었으면 다시 생성하지 않는다.

heavy 시작은 정상1회와 기계적 복구 예비1회를 합해 최대2회다.
예비는 모델 성능 탐색이 아니라 실행 계약 오류 복구에만 사용한다.
실제 모델 적재·forward·step·decode 횟수는 각각 기록한다.

final latent 저장 뒤 decode가 실패하면 sampler를 반복하지 않는다.
저장된 latent로 VAE-only 복구를 최대1회 허용한다.
MP4 포장 오류는 기존 raw/PNG로 고친다.

실제 외부 GPU 충돌·OOM·메모리 압박·관측 실패는
우회하거나 자동 재시도하지 않는다.
다른 서비스·프로세스를 종료하지 않는다.
현재 가드 임계값·allowlist·시스템 설정은 변경하지 않는다.

원래 source/reference/imagegen 파일과 checkpoint는 보존한다.
이번 정상 산출물은 새 종료 앵커1장과 새 영상1개다.

전체 작업 상한90분.
마지막15분은 기록·전달·종료에 남긴다.
시간 상한은 작업 범위이며 성능 예상치가 아니다.


## 10. 평가 — 앵커 교정과 영상 전파를 분리한다

비교 화면:
SOURCE
TARGET REFERENCE
START ANCHOR
OLD END ANCHOR / CORRECTED END ANCHOR
C002 MOV / C004 CORRECTED_END

같은 시간 인덱스로 전체33장을 비교한다.
고정 시트:
0/4/8/12/16/20/24/28/32

분석 구간:
- 중간 진행:1~28
- 종료 접근:29~31
- 실제 마지막 출력:32

종료부만 좋아진 것과 중간 동작까지 좋아진 것을 구분한다.
새 영상이 끝에서만 새 앵커를 따르는지,
중간의 머리·몸 높이·발 배치까지 바뀌는지 본다.

평가 축:
1. 앵커 자체의 원본 자세 적합성
2. 시작/종료 앵커의 target 외형 일관성
3. 실제 출력의 각 앵커에 대한 충실도
4. 전체 접근·위치·크기 진행
5. 머리 방향·몸통 높이
6. 관측 가능한 앞발의 전후 배치와 순서
7. target의 검정/흰 특징과 원본 외형 회귀
8. 배경·주변 객체의 변화
9. 형태 붕괴·다리 중복·급격한 종료 전환
10. 실제 연속 품질과 비용

수식적인 pixel error 하나로 개체·동작 성공을 판단하지 않는다.
새 출력과 새 앵커의 오차는 보조 지표다.
더 쉬운 앵커로 바뀌어서 작은 오차가 나올 수도 있음을 기록한다.

정확한 관절·발 접촉 GT가 없으면 UNCERTAIN으로 둔다.
정적인 낮은 발 위치만으로 접지 성공을 선언하지 않는다.
출력 시간축을 이동하거나 warp해서 더 맞아 보이게 만들지 않는다.

새 종료 앵커는 자세 외에도 얼굴·털·조명·배경을 바꿀 수 있다.
따라서 비교는 “교정 앵커 전체를 바꾼 효과”다.
“종료 자세 하나만 바꾼 순수 인과효과”라고 주장하지 않는다.

배경 변화가 이미 새 앵커에 있는지,
앵커에는 없고 영상 생성 중 생긴 것인지 구분한다.

실제 연속 재생을 지각 검수했다면
검토 주체·재생 속도·확인 내용을 기록한다.
정적 시트·브라우저 재생 테스트·ffmpeg decode만 했다면
temporal=UNVERIFIED를 유지한다.


## 11. 판정과 종료 기준

앵커 판정과 영상 판정을 별도로 남긴다.

영상 판정 후보:

ENDPOINT_GAIN_ONLY
- 종료부와 마지막 앵커 충실도는 좋아졌으나
  중간 동작의 추가 이득은 확인하지 못함.

MIDCLIP_GAIN
- 중간 머리·몸통·관측 가능한 발 진행까지 개선되고
  target 외형·장면의 뚜렷한 회귀가 없음.
- 단일 사례의 교정 앵커 효과로 한정.

TRADE_OFF
- 자세 일부는 좋아졌지만
  target 외형·장면·형태에 손상이 동반됨.

NO_ESTABLISHED_GAIN
- 교정 앵커를 사용했으나 기존 MOV보다
  동작·형태의 명확한 추가 이득을 확인하지 못함.

WORSE
- 결합 품질이 명확하게 악화됨.

INCONCLUSIVE
- 새 앵커가 요구를 충분히 만족하지 않거나
  부수적 변화·입력 불일치 때문에 해석하기 어려움.

앵커가 부적합해 영상을 생략한 경우:
ANCHOR_UNSUITABLE / VIDEO_NOT_RUN
로 기록한다.
영상 방법이 실패했다고 세지 않는다.

개선 여부와 관계없이 이번 비교 뒤 종료한다.
앵커를 또 만들거나 더 유리한 source 구간을 찾아가지 않는다.
C-003 내부 구조선의 과거 판정을 뒤집지 않는다.
이번 성공이 있다 해도 일반화된 동작 전이나 새 알고리즘 성과로 확대하지 않는다.


## 12. 한국어 수식·코드 해설

이번 실제 변화에 연결된 짧은 해설을 작성한다.

기호:
V:원본33프레임
A0:고정 시작 앵커
A32:기존 종료 앵커
A32':교정 종료 앵커
L:기존 동적 윤곽
P:기존 텍스트 조건
epsilon:동일 초기 noise

기존:
Y=H_theta(A0,A32,L,P;epsilon)

새 비교:
Y'=H_theta(A0,A32',L,P;epsilon)

설명할 것:

1. 양끝 상태와 중간 구조 조건이 충돌한다는 의미.
   조건이 많다고 항상 동시에 만족할 수 있는 것은 아니다.

2. 원본 자세 보존과 target 체형의 픽셀 일치는 다르다.
   같은 행동 상태라도 다른 개체의 실루엣은 달라질 수 있다.

3. 종료 이미지가 바뀌면 중간 생성도 바뀔 수 있는 경로.
   시간 VAE와 영상 Transformer가 정보를 결합한다는 사실과
   실제 중간 개선 여부는 별개의 검증임을 설명한다.

4. 이번 VACE 조건 연결.
   U=Encoder((1-G)*Normalize(X))
   R=Encoder(G*Normalize(X))
   마지막 X만 바꾸는 것이 어떤 논리 입력에 영향을 주는지
   실제 코드와 연결한다.

5. 33프레임·9 latent 시간 위치·50 생성 step의 차이.

6. 앵커 변경 효과와 새 생성 알고리즘의 효과를 구분한다.
   이번은 알고리즘 신규성 실험이 아니라 입력 충돌 진단이다.

7. 모든 실패를 새 모델로 해결하지 않고,
   피드백이 잘못된 입력 단계로 돌아가는 이유.

직관 → 수식 → 실제 입력·함수 → 관측 → 한계 순서로 작성한다.
이론만 길게 복제하지 않는다.
결과가 가설과 다르면 그대로 설명한다.
