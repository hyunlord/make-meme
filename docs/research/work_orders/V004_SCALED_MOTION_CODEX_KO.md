## 0. V-003에서 확인한 것

Claude가 원본·Kling·K1·K3을 같은 프레임으로 잘라 비교했다.

- **성공**: 여섯 영상 모두 두 개가 처음부터 끝까지 뒷발로 서서 춤춘다. 래브라도·IG 외형도 영상 내내 유지된다. M1의 네 발 붕괴는 해결됐다.
- **실패**: 원본에서 가장 빠른 동작인 **프레임 24~30의 발차기**가 맞지 않는다. 원본과 Kling은 등을 보이며 다리를 왼쪽 위로 높이 찬다. K1은 오른쪽 옆으로 차고 일찍 정면으로 돈다. K3은 발차기가 없다.
- **K3(`replace`)는 이 장면에서 제외한다.** 키프레임 사이 동작이 죽고 잔상이 생겼다.

**사용자 결정: 래브라도는 원본보다 크게 유지하고, 동작 일치도 포기하지 않는다.** 그래서 두 요구가 충돌하던 지점 두 곳을 직접 고친다.

1. **윤곽과 체형의 충돌.** canny는 원본의 작은 개 윤곽인데, 앵커의 래브라도는 더 크다. 모델이 둘 사이에서 타협하며 동작이 흐트러진다. → 원본 윤곽을 **래브라도 크기로 확대**해서 조건으로 준다. 다리 방향과 위치는 원본 그대로, 크기만 앵커와 맞춘다.
2. **시간 해상도 부족.** 발차기는 6~8프레임 안에 끝나는데, LTX는 8프레임을 latent 하나로 압축한다. → 발차기 구간에 **앵커를 4프레임 간격으로 추가**하고, 별도 변형에서 **2배 느린 시간축으로 생성한 뒤 한 프레임씩 건너 뽑는다.**

## 4. 확대 윤곽 조건 (CPU, 생성 전 고정)

V-003에서 쓴 1152×640 canny(CannyEdgePreprocessor 92/200)를 기반으로, 개체마다 프레임별로 다음을 한다.

1. **배율 결정(클립 전체 고정값, 개체별)**: 수용 앵커 11장(기존 7 + 신규 4 중 수용분)에서 앵커 bbox 높이 ÷ 원본 같은 개체 bbox 높이를 구해 **중앙값**을 쓴다. 프레임마다 바꾸지 않는다(크기 떨림 방지). IG도 같은 방식으로 구하되, 0.9~1.1이면 1.0으로 둔다. 값과 근거를 PLAN에 기록한다.
2. **원본 개체 윤곽 잘라내기**: 원본 SAM 마스크(반사 제외 실제 개)를 4px 팽창한 영역 안의 canny만 개체 윤곽으로 쓴다.
3. **확대 기준점**: 원본 bbox의 **아래쪽 가운데**(발 위치)를 기준으로 확대한다. 서 있으면 발이 바닥에 붙은 채로 커지고, 점프 중이면 발 높이가 유지된다.
4. **반사**: 반사 개체(track2·3)는 같은 배율로 반사 bbox의 **위쪽 가운데**를 기준으로 확대한다. 실제 개와 반사가 바닥선에서 계속 붙어 있게 하기 위해서다.
5. **합성 순서**: 배경 canny(개체·반사 영역을 지운 원본 canny) → IG 윤곽 → IG 반사 → Lab 반사 → Lab 윤곽. 래브라도가 앞에 있으므로 겹치는 곳은 Lab 윤곽이 덮는다.
6. 화면 밖으로 나가는 부분은 잘린다. 잘린 픽셀 비율을 프레임별로 기록한다.

**사전 점검(생성 전, 기록만)**: 각 키프레임 위치에서 확대 윤곽으로 만든 Lab 영역(확대된 원본 마스크)과 앵커의 Lab SAM 마스크의 IoU를 기록한다. 확대 윤곽과 앵커가 서로 맞는지 보는 수치다. 키프레임 전체 평균이 0.5 미만이면 결과를 해석할 때 주의하라고 RESULTS에 적되, 생성은 진행한다.

검토용으로 원본 canny / 확대 canny / 앵커를 겹친 비교 시트(키프레임 11개)를 만든다.

## 7. 예산과 순서

| 단계 | 승인량 |
|---|---:|
| imagegen | 4장 신규 + 보정 최대 4회 = 최대 8회 |
| SAM | 신규 앵커 최대 8장, 출력 6개 |

순서: 인수 → 사전 commit(설정·위치·배율 산정 규칙) → 신규 앵커 4장(게이트) → 배율 산정·확대 윤곽·비교 시트 → **중간 전달**(앵커 + 윤곽 시트) → S2-s1 → S1-s1 → S3-s1 → **중간 전달**(seed 1 세 개) → seed 2 세 개 → 후합성 → 측정 → 뷰어 → 전달.
