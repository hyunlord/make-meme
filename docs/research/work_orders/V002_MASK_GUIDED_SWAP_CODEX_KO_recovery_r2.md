# V-002 실행 의뢰 개정 2 — 복구 승인 기록

사용자가 같은 V-002의 복구를 승인했다. r1과 최초 실행 기록은 보존한다. 이 문서는 새 연구 번호를 만들지 않고 이번 승인 범위만 기록한다. 상세 사전 실행 기록은 [RECOVERY_R2.md](../experiments/V-002-mask-guided-swap/RESUME_R1/RECOVERY_R2.md)를 따른다.

## 승인된 변경

- 기준 착수 2026-11-04T19:25:55Z, 종료 2026-11-05T01:25:55Z. 마지막 30분인 00:55:55Z부터 기록·전달에 쓴다.
- 재부팅 후 M2 이전 worker가 없고 완성 출력도 없음을 확인한 경우 M2를 같은 입력·설정으로 **한 번만 재시작**한다. 과거 STARTED receipt와 중간 진행을 보존하고 별도 시도로 기록한다.
- **M1의 SAM 측정·검토물 전달을 먼저 완료**한 뒤 M2 재시작과 M3로 진행한다.
- Spark 내부 tmux 또는 사용자 unit으로 작업 수명을 관리한다. 기존 실행 가드는 변경하지 않는다.
- 이번 복구에서 **14B·LTX canny는 NOT_RUN**이다. 자동 실루엣 IoU 선택으로 후속 모델을 실행하지 않는다. 실제 결과 전달 뒤 사용자 판단으로 다음 단계를 결정한다.
- 기존 E1 사용자 판정과 자동 IoU의 차이를 기록한다. IoU는 설명값이며 동작 추종의 단독 신뢰 기준이 아니다. HUMAN_REVIEW_PENDING과 temporal=UNVERIFIED를 유지한다.

## 실행 전 확인 사실

Spark 새 부팅은 2026-11-05 04:22:30 KST, 이전 journal 마지막 시각은 03:59:08 KST다. M2 worker 부재와 STARTED receipt를 확인했으며 저장된 마지막 진행은 45 model_fn call / 22 scheduler step, 완성 출력은 없다. 이전 관측 상실 당시의 44 call / 21 step 기록을 소급 변경하지 않는다. 재부팅 사실만으로 원인을 OOM·NVRM으로 단정하지 않는다.

그 밖의 모델·입력·앵커·seed·품질 판정 방식과 안전 중단 조건은 유지한다. 다른 프로세스 종료·가드 완화·새 학습·새 앵커·품질 재시도는 승인하지 않는다. 이 기록은 실행 완료 보고가 아니다.
