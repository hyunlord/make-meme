현재 loader·서비스 부재 정책·가드 구현은 고정한다.
이번 UNKNOWN_GPU_PID를 통과시키기 위해 정책이나 allowlist를 변경하지 마.

1. 점유 작업을 먼저 알려줘

이미 저장한 비공개 receipt에서 차단된 GPU 프로세스의
사용자·프로그램·시작 시각·관련 프로젝트/부모 프로세스를 확인해줘.

사용자가 알아볼 수 있는 작업 이름으로 요약하고,
현재도 같은 프로세스가 존재하는지 읽기 전용으로 한 번 확인한다.
PID 재사용 가능성이 있으므로 PID 숫자만으로 동일 작업이라고 하지 마.

개인 경로·명령 인자의 비밀정보는 공개 GitHub에 올리지 않는다.
관련 없는 프로세스 전체를 조사하지 않는다.

작업이 계속 존재하면 무엇이 점유 중인지 보고하고 종료한다.
임의 kill·서비스 중지·자동 allowlist 등록·자동 대기는 하지 않는다.
같은 내용의 대형 ZIP이나 새로운 가드 설계를 만들지 마.

2. 이미 종료됐다면 기존 조건으로 잔여 비교를 완료해줘

이번 재개에만 기존 OPTIONAL_EXPECTED_ABSENT 정책을
동일한 내용으로 명시 적용한다. 이전 시도의 승인을 영구 연장하지 않는다.

기존 시작 표본·서비스/외부 GPU·메모리·swap 검사를 통과하면
미사용 STEP 최대1회와 해당 decode 최대1회를 수행한다.
시작 직전에 충돌이 다시 나타나면 중단한다.

새 모델 로딩 시도 한도는 그대로이며 자동 재시도하지 않는다.
BASE·CONTROL·encoder·이미지·학습은 다시 실행하지 않는다.
입력·noise·모델·clean constraint·E/M·평가 기준도 바꾸지 않는다.

3. 결과를 보고 B-034를 마무리해줘

BASE / FINAL_LATENT_ONLY / STEP을 동일 RGB_POST에서 비교한다.
목표 클래식 차량이 없으면 배경 개선과 별개로 결합 목표 FAIL이다.
실제 연속 검수를 하지 않았다면 temporal=UNVERIFIED를 유지한다.

기존 실패·운영 차단·시도 장부를 보존하고,
HISTORY/ROADMAP에는 상태 변화와 최종 비교만 간결하게 연결한다.

점유 작업이 있는 동안 반복 확인이나 자동 재개를 예약하지 않는다.
실행했다면 새 결과만 compact/full로 전달하고
추가 실험은 시작하지 않는다.
