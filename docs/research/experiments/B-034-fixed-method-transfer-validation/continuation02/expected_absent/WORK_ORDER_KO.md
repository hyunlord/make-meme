# B-034 잔여 STEP 완료 — 수동 서비스의 한정 비가동 운영 승인

저장소: hyunlord/make-meme
브랜치: docs/b-research-20261022

이번 지시는 기존 service_resume 계획의
‘관리자 inactive/stopped 증명이 있어야만 진행’ 조건을
이번 잔여 실험에 한해 명시적으로 대체한다.

과거 서비스가 정상 종료됐다고 선언하는 것이 아니다.
기존 UNKNOWN·BLOCKED와 실패 예산은 그대로 보존한다.

## 1. 이번 실행의 운영 승인

8190 큐 서비스는 선택된 연구 경로의 필수 의존성이 아니라
다른 작업을 보호하기 위한 관측 대상임이 확인됐다.

이번 잔여 STEP·decode 작업 동안
8190 서비스와 별도의 GPU 작업을 사용하거나 시작하지 않는
운영 전제로 진행한다.

이 승인에는 다른 서비스의 시작·종료·재시작,
다른 프로세스 강제 종료, driver·swap 변경이 포함되지 않는다.

기존 수동 배포에 관리자 인터페이스가 확인되지 않았다는 이유만으로
같은 관리자 검색과 증거 ZIP 작성을 반복하지 마.
이를 해결하기 위해 새 systemd 서비스나 관리자를 설치하지도 않는다.

## 2. 과거 상태와 이번 정책을 분리

STOPPED_CONFIRMED를 소급 활성화하지 않는다.
새 한정 정책을 OPTIONAL_EXPECTED_ABSENT로 기록한다.

관측 통과 상태는 EXPECTED_ABSENT_OBSERVED다.
의미는 다음으로 한정한다.

“사용자가 이번 실행에서 서비스를 사용하지 않도록 승인했고,
현재 관련 실행 흔적과 충돌이 관측되지 않았다.”

과거 정상 종료, 미래 자동 시작 부재,
장비 전체의 강제 독점을 증명했다고 쓰지 않는다.

이 정책은 이번 attempt의 시작부터 종료까지만 유효하다.
전역 기본 정책이나 다른 실험의 허용 목록을 변경하지 않는다.

## 3. 실제 시작 조건

최신 HEAD와 로컬 실행 상태부터 확인한다.
같은 STEP이 이미 실행 중이거나 완료됐으면 중복 실행하지 않는다.

기존에 확인한 서비스 launcher·실행 경로를 기준으로,
현재 프로세스·자식 프로세스·8190 listener를 확인한다.
개인 홈 전체나 모든 서비스 관리 체계를 다시 탐색하지 않는다.

시작 직전 약2초 간격의3표본에서 다음을 확인한다.
- 관련 서비스 프로세스·자식·8190 listener 없음
- 외부 GPU 작업 없음
- 중복 연구 worker 없음
- MemAvailable 기존 시작 기준72GiB 이상
- swap 사용량0
- 각 관측 명령이 정상적으로 완료됨

권한 부족·관측 명령 실패를 ‘없음’으로 처리하지 않는다.
8190 listener나 관련 서비스 프로세스가 있으면
이번 EXPECTED_ABSENT 경로로는 시작하지 않는다.
그 프로세스를 종료하거나 새 PID를 자동 허용하지 마.

큐는 접속 불가일 경우 UNAVAILABLE/counts=null로 기록한다.
관련 프로세스·listener 부재까지 확인되고
이번 정책이 명시적으로 활성화된 경우에만
큐 연결 거부를 시작 차단 조건에서 제외한다.

그 밖의 endpoint 오류·모순된 관측은 차단한다.
과거 allowlist를 빈 목록으로 덮어쓰지 말고,
과거 서비스 snapshot과 이번 부재 기대 정책을 따로 보존한다.

## 4. 실행 중 보호

기존 메모리24GiB headroom·swap0·프로세스 신원 감시를 유지한다.

관련 서비스·listener 또는 외부 GPU 작업이 새로 나타나면
이번 연구 worker만 안전하게 중단하고 기록한다.
외부 작업을 중지하거나 큐를 삭제하지 않는다.

수동 launcher가 미래에 절대 실행되지 않는다는 증명을 요구하지 않는다.
대신 현재 관측과 실행 중 감시의 한계를 명시한다.

기존 연구 작업용 중복 실행 잠금이 있으면 재사용한다.
잠금이 없으면 이번 worker의 중복만 막는 작은 비차단 잠금을 사용할 수 있다.
이를 다른 프로그램까지 통제하는 GPU 독점 장치라고 보고하지 않는다.

검증된 자체 worker 생애주기·종료 신원 처리를 재사용한다.
단계 사이 fresh safety를 다시 확인하고,
STEP 프로세스가 종료된 뒤에만 VAE를 실행한다.

## 5. 최소 정책 구현·검사

preflight와 실제 supervisor가 같은 정책 설정을 읽게 한다.
preflight에서만 허용하고 실제 worker가 이전 정책으로 차단되지 않게 한다.

새 정책에 필요한 CPU 검사만 추가한다.
- 수동 서비스 부재 + 정상 관측: 한정 허용
- listener 또는 서비스 프로세스 존재: 차단
- 외부 GPU 작업: 차단
- 관측 실패·권한 부족: 차단
- 실행 중 서비스 재등장: 자체 worker 중단
- 명시적 정책 승인 없음: 기존 차단 유지

이미 통과한 loader 초기화·CPU24개 검사를
별도 프로젝트처럼 다시 수행하지 않는다.
B007E_LOADER_REPORT의 공통 초기화와 preflight는 그대로 사용한다.

정책 변경·실제 설정·코드 해시를 실행 전에 기록한다.
가드 자체를 끄거나 항상 PASS를 반환하는 수정은 금지한다.

## 6. 남은 연구 실행

이번 CPU 수정·안전 확인이 통과하면
별도 의뢰를 기다리지 말고 같은 작업에서 남은 비교를 완료한다.

이미 승인됐으나 미사용인 CONTINUATION_02 예산만 사용한다.
- STEP 모델 로딩·full sampler 시도 최대1회
- 40step·80forward·clean constraint40회
- 성공한 final latent의 VAE decode 최대1회
- 자동 재시도0회

BASE·CONTROL 재생성/재decode,
source/reference encoder, 이미지 생성,
학습·새 모델/패키지 설치·다운로드는 모두0회다.

기존 입력·참조·noise·RNG·scheduler·E/M·평가 crop과
B-033 clean_constraint.py를 유지한다.
prompt·강도·스케줄·mask·LoRA·attention·RoPE를 바꾸지 않는다.

기존 final latent와 cache는 읽기 전용으로 재사용한다.
새 final latent는 decode 전에 원자 저장·검증한다.
decode 실패로 sampler를 다시 실행하지 않는다.

## 7. 평가와 연구 종료

기존 BASE / FINAL_LATENT_ONLY / 신규 STEP을
raw와 동일 RGB_POST에서 비교한다.

클래식 target의 노출 바퀴·긴 차체·열린 상부,
SUV/왜건형 회귀, 접근 동작, 보호 장면,
경계·접촉·그림자를 따로 판정한다.

배경만 좋아지고 target 외형이 없으면 결합 목표 FAIL이다.
BASE부터 없던 target이 그대로 없다는 것을
target non-regression PASS로 보고하지 않는다.

실제 연속 시청을 하지 않으면 temporal=UNVERIFIED다.
비강체 앵커 실패·영상 NOT_RUN도 그대로 남긴다.

이번 STEP 효과의 추가 이득·무효·회귀를 기록하고
B-034를 더 이상의 설정 탐색 없이 마무리한다.

## 8. 시간·기록·전달

전체 상한90분, 마지막15분은 보존·전달에 남긴다.
작은 정책 구현·확인은 목표20분으로 제한한다.

실제 충돌·관측 권한 문제·입력 오류가 있으면 중단한다.
단, 이미 확인한 ‘수동 배포의 관리자 부재’만을 이유로
재조사와 재승인 루프를 반복하지 않는다.

HISTORY·ROADMAP에는 다음을 분리해 기록한다.
- 이전 정책에서 중단한 사실
- 이번 사용자의 한정 정책 변경 승인
- 실제 live safety 관측
- 모델 실행·영상 품질 결과

공개에는 비민감 코드·문서·요약만 기록한다.
PID·개인 경로·전체 command·조건 tensor·가중치는 공개하지 않는다.

최종 비교 영상·뷰어·보고서는 작은 compact에,
새 raw/latent는 full에 보존한다.
기존 대형 raw와 과거 ZIP을 반복 중복 포장하지 않는다.
Spark/Mac 전송·CRC·해시·추출을 실제 범위에서 검증하고
commit/push와 원격 SHA를 확인한다.

추가 seed·새 사례·학습·모델·후속 실험은 자동 시작하지 않는다.
