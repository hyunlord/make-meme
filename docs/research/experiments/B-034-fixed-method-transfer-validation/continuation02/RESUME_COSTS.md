# RESUME_01 비용과 안전 차단

기존 Spark 연결은 복구됐다. 기존 Python으로 실제 STEP_S/STEP_D root의 동일 worker `--preflight-only`를 부모 loader-report 변수 없음/과거 값 두 상태에서 각각 실행했다. 4회 모두 성공했고 실제 CUDA/Torch/Wan import, 모델 적재, loader.json 또는 worker-attempt 생성은 없었다. 동일 Spark Python CPU fixture24개도 PASS다.

그러나 fresh live guard는 **OBSERVATION_FAILED**다. 보호 서비스 queue endpoint가 connection refused이고, 기존 허용 PID의 정확한 신원도 현재 존재하지 않는다. boot identity는 CONT01 기록과 다르다. GPU PID가 없고 MemAvailable 약100.152GiB, swap0인 사실은 서비스/queue 확인 실패를 무효화하지 않는다. queue 데이터의 기본 빈 배열을 실제 idle PASS로 해석하지 않는다.

새 supervisor/model/sampler/decode는 모두0회이며, CPU 준비·전송만 수행했다. 기존 BASE/CONTROL·mask·cache·noise는 그대로 참조했다. 새 root 생성 전 첫 rsync가 부모 경로 부재로 실패한 CPU 준비 오류는 보존하며, 새 continuation 경로만 만든 뒤 전송했다. GPU 예산은 사용하지 않았다.

현재 service를 시작하거나 허용 PID를 갱신하지 않았고 guard도 변경하지 않았다. 과거 BLOCKED_SSH 및 CONT01 loader 실패는 유지한다. 실제 수치는 RESUME_MEASUREMENTS.json, 검증 범위는 RESUME_CPU_REPORT.json을 따른다.
