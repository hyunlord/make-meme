# V-001 해설

반사 제외 규칙으로 대체 구간과 공통 앵커를 확정했다. 개정3 E1 조건 인코딩 실패를 보존하고, 개정4에서 승인된 1152×640으로 E1 영상 2개를 실제 생성했다. E2 개정3은 적재 중 PSI 가드로 중단됐으며 개정4는 probe 후 49프레임 첫 seed를 시작했으나 원격 접근이 유실되어 실행 결과가 미관측이다. E1 출력 SAM 측정은 Spark 접근 불가로 NOT_RUN이며 사용자 품질 검토는 HUMAN_REVIEW_PENDING이다.

1. **첫 프레임과 구조 조건의 역할.** LTX는 앵커를 인코딩해 첫 프레임 latent를 조건으로 고정하고, IC-LoRA는 시간별 depth를 별도의 reference 조건으로 전달한다. 공식 two-stage는 먼저 출력의 절반 해상도에서 생성한다. 실제 Union ref0.5 메타데이터는 reference를 다시 2로 나눈다. 따라서 1024×576 → 512×288 → 256×144가 되며, reference VAE의 공간 배수 32 조건을 만족하려면 최종 높이·너비가 128의 배수여야 한다. 576은 이를 만족하지 않아 조건 VAE에서 실패했다. 이는 체형·동작 품질 실패가 아니다. 입력 depth 파일만 리사이즈해도 내부 전처리가 같은 크기로 강제하므로 해결되지 않았다. 개정4에서는 출력 자체를 승인된 1152×640으로 바꿔 stage 576×320, reference 288×160을 확보하고 두 결과를 생성했다. [고정 IC-LoRA 실행 코드](https://github.com/Lightricks/LTX-2/blob/e98f6d927d83c92ef2be6aec76c8440b19306e39/packages/ltx-pipelines/src/ltx_pipelines/ic_lora.py#L907), [reference 크기 계산](https://github.com/Lightricks/LTX-2/blob/e98f6d927d83c92ef2be6aec76c8440b19306e39/packages/ltx-pipelines/src/ltx_pipelines/iclora_utils.py#L134).
2. **Bernini가 받는 두 조건.** Renderer의 `video`는 원본 구간을 전처리·VAE encode하여 `multi_video_vae_latents`로, `images`는 참조 앵커를 각각 encode하여 `multi_image_vae_latents`로 만든다. 두 조건과 텍스트 토큰을 같은 `model.sample`에 전달하며 출력 크기는 전처리된 원본 영상에서 얻는다. RV2V의 참조 이미지 목록은 단일 이미지 편집용 `image` 인자와 구별된다. `use_pe=false`인 renderer-only 경로에는 외부 planner 호출이 없다. Import 분리 패치는 renderer 계산을 바꾸지 않았다. 이 연결 확인은 실행 결과의 동작 추종 증거가 아니다. [고정 renderer 구현](https://github.com/bytedance/Bernini/blob/e6c2cf11843470b08491745947abcba9c3c6b079/bernini/pipeline.py#L302).
3. **C 트랙과 조건의 밀도 차이.** C의 양끝 앵커와 약한 중간 조건에서는 중간 동작을 모델이 채워야 했다. 이번에는 한 앵커가 외형을, 조밀한 원본 영상 또는 depth가 시간별 구조를 제공한다. 앵커 게이트 통과나 depth 생성 완료만으로 시간 전파 성공을 선언할 수 없다.
4. **Depth와 체형 변경의 충돌 가능성.** 원본 depth에는 기존 개체의 크기와 실루엣이 포함된다. 더 큰 Lab으로 바꾸라는 앵커와 원본 구조를 유지하라는 조건이 충돌할 수 있다. E1 영상은 확보했지만 출력 SAM 측정과 사용자의 재생 검토가 아직 없어 이 가설의 성립 여부를 판정하지 않는다. 위치·체형·외형·배경은 각각 측정하고 최종 품질은 `HUMAN_REVIEW_PENDING`으로 남긴다.
