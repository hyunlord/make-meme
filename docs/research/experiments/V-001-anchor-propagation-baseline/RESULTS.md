## 보존한 개정3 중단 기록

개정3에서 E1의 기존 Gemma 접근은 회복됐고 필요한 가중치 다운로드를 완료했다. Video Depth Anything은 1회 호출(내부 forward 4회), 44.7085초로 원본 73프레임 depth를 만들었다. Matplotlib writer 오류는 보존 raw를 사용한 CPU 포장으로 복구했으며 모델을 다시 실행하지 않았다. E1 probe는 약 18.9813초 뒤 조건 인코딩에서 실패하여 첫 denoising step 시간도 얻지 못했다. 576→288→144의 reference 높이가 VAE 공간 32배수를 만족하지 않는다. 사전 CPU 검사에서 이 추가 배수 조건을 놓친 기술적 미완료다.

E2는 고정 snapshot 126,200,552,703 bytes와 index가 참조하는 27개 shard 다운로드를 완료했다. 개정3의 E2 전용 100GiB worker 예외 아래 적재를 시작했으나 약 75.6초 후 실제 guard가 중단했다. PSI full avg10>25%가 00:42:12.673–00:43:13.345 KST 동안 약60.662초 지속됐고 최대76.64%였다. 시작 가용113.622GiB, 실행 중 최저74.524GiB, 관측 RSS 최대97.954GiB(표본 하한), cgroup peak98.033GiB였다. 기존 MemoryHigh98GiB의 high event1417회가 기록됐으며 OOM과 worker swap은0이다. 총 swap-out578.09MiB였다. 실제 시스템 여유 부족이나 OOM으로 바꾸어 해석하지 않는다. 이 시간이나 두 번째 expert 적재 진행률을 샘플링 성능으로 외삽하지 않는다. 당시 동일 단계를 자동 재시도하지 않았고 두 엔진 모두 생성 출력은 없었다. 이후 개정4의 명시적 승인을 별도로 기록하고 E1을 재개했다.

개정2의 Gemma 403 및 E2 64GiB 사전 한도 차단은 과거 기록으로 보존한다. 개정3의 실제 실행 실패를 과거 차단 원인으로 대체하지 않는다.

## 개정4 해상도와 depth 재사용

공통 1280×720 원본·앵커를 1152×648로 비율 유지 리사이즈하고 위·아래 4px씩 잘라 1152×640으로 맞췄다. 기존 1024×576 raw depth도 동일한 화면 기하로 CPU 리사이즈·크롭하고 공식 전체 구간 min/max 정규화와 grayscale CRF18 포장을 적용했다. 추가 VDA 호출은 0회이며 원본 depth와 개정3 실패 산출물은 보존했다. 실제 가중치 메타데이터와 고정 소스로 128배수 조건을 확인한 기록은 `E1_GEOMETRY_AMEND4.json`이다.
