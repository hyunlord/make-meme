# C-004 결과 — 앵커의 부분 교정, 영상 동작 이득 미입증

**앵커는 PARTIAL_BUT_USABLE, 영상은 NO_ESTABLISHED_GAIN이다.** 새 종료 앵커의 얼굴·주둥이는 조금 올라갔지만 원본 상태와의 큰 충돌이 해결됐다고 보기 어렵다. 실제 영상 한 개를 생성해 기존 C002 MOV와 비교했으며, 중간 머리·다리 진행이나 종료 전환의 명확한 개선을 확인하지 못했다. 기본 채택하지 않는다. **temporal=UNVERIFIED**다.

## 앵커와 영상의 실제 변화

| 질문·구간 | 관측과 판정 |
|---|---|
| 앵커 자체 | 기존 끝보다 주둥이가 약간 높고 얼굴이 더 정면으로 보인다. 몸통과 보이는 앞발 관계는 대체로 유사하다. source도 이미 머리가 낮아 일반적인 기립 자세가 정답은 아니다. 큰 충돌 교정 성공은 미입증이다. |
| target/start 일관성 | 검정 긴 털·흰 얼굴/주둥이/가슴/발의 거친 특징이 남고 크림색 source로의 뚜렷한 회귀는 없다. 얼굴 무늬와 목의 흰 털이 바뀌므로 정확한 개체 일치는 PARTIAL이다. |
| 중간1–28 | 새 영상의8/16 등에서 얼굴이 더 정면이고 코가 조금 높다. 그러나 머리·몸통·앞발 사건의 순서가 source에 더 가깝다는 일관된 증거는 없다. 접근·크기와 거친 앞발 배치 패턴은 두 영상에서 비슷하다. |
| 종료 접근29–31 | 두 영상 모두 머리가 잔디 가까이 낮아지고 앞발이 뻗는 전환이 남는다. source의 진행과의 차이가 해결되지 않았다. 정적 인접 프레임만으로 전환의 지각적 매끄러움을 PASS로 하지 않는다. |
| 실제 출력32 | 새 출력의 주둥이가 기존보다 높아지는 변화는 보이지만 source도 낮은 머리여서 자세 정확도 개선으로 확정하지 않는다. 마지막 출력을 새 앵커로 덮어쓰지 않았으며 pixel-exact 앵커 재현은 아니다. |
| 배경·형태 | 잔디·수풀의 큰 배치는 남지만 질감 변형과 패치가 있다. 새 영상16–24의 오른쪽 전경 줄기/잎 같은 모양은 source·새 앵커에 없고 기준 영상보다 두드러진다. 새 영상의 넓어진 흰 목털도 세부 외형 변화다. 큰 다리 중복은 두드러지지 않지만 관절·접촉 정확도는 UNCERTAIN이다. |
| 연속 품질 | 전체33장, 고정9장,29–32와 같은 좌표 확대를 정적으로 검토했다. 브라우저 재생·파일 decode 검사는 했으나 실제 연속 지각 검수는 하지 않아 UNVERIFIED다. |

검토 주체는 실행 에이전트와 같은 세션의 별도 에이전트다. 독립 human 평가가 아니다. 화면 좌우를 해부학적 좌우로 바꾸지 않았고 시간 정렬·warp·좋은 프레임 선별을 하지 않았다.

앵커의 잔디·빛·얼굴 변화는 생성 전부터 존재한다. 반면 위의 오른쪽 전경 모양과 확대된 흰 목털은 새 영상에서 더 두드러지는 변화다. 이 구분은 발생 원인을 단정하는 것이 아니다. 비교 대상은 교정 앵커 **전체**의 변경이며 자세 한 변수의 순수 인과효과가 아니다.

## 실행과 불변 조건의 증거

계획·정확한 native 입력/프롬프트를 `248af7c`에 먼저 고정했다. 실제 native imagegen1회/후보1장을 받아 원출력을 보존하고 C001 aspect-fit LANCZOS/blackcanvas 규칙만 적용했다. 영상 전 앵커 판정·조건을 `e5d41df79bd149cb61d12f56e2228efc5f589eff`에 commit/push하고 원격 SHA를 확인했다. [앵커 판정](ANCHOR_REVIEW.md), [계보](ANCHOR.json).

영상 모델 코드는 C002 원본 그대로이며 effective config는 end_anchor/output만 다르다. 실제 조건 RGB0..31은 기준과 동일하고32만 바뀌었다. G33과 압축 마스크도 같다. 논리 reactive 입력은 동일하며 inactive의 마지막 RGB만 변경됐다. C003 구조선·새 SAM·학습·새 모델은 없다.

실제 최초 noise hash는 C002의 `cf71cc3501ff09f876a384a20e9aedea41fb7eaaf956e5da52e8f777c9fbf9ba`와 같고 shape는[1,16,9,60,104]다. VACE context는[1,96,9,60,104] BF16 finite이며 다른 hash를 갖는다. mask64 hash는 C002와 같고 scale1.0이다. 추가 forward0이다. 입력 변경이 전달됐다는 증거와 품질 이득은 분리한다. [NUMERICS](NUMERICS.json).

실제50step·100 model_fn call·33프레임을 완료했다. final latent 원자 저장/readback exact, raw tensor와 전체 무손실 프레임을 별도 보존했다. GPU heavy1회, sampler1회, decode1회이며 예비·VAE 복구·품질 재시도0이다. 최소 MemAvailable95,026,089,984B, 자체 swap/OOM/high 증가0, 전역 swap1,806,336B 안정 상태와 GLOBAL_SWAP_WARNING을 보존했다. 현재 C003 guard는 변경하지 않았고 COMPLETE/CLEAR·정상 worker0·cleanup오류0·최종 cgroup REMOVED다. 종료 후 자체 활성 unit와 GPU process0을 확인했고 다른 작업을 시작·종료하지 않았다.

## 비용과 기계적 오류

Native 도구17.101초, 영상289.751744초(약4분50초)였다. 내부 image model 식별자와 청구 금액은 도구가 노출하지 않아 UNKNOWN이다. 유료 API 전환·다운로드·설치·SAM/구조 추출·학습0이다. 검토 뷰어 생성5.216초, 자동 QA5.077초이며 따로 재지 않은 수동 검토·전기·구독 배분 비용은 null로 남긴다.

모델 전 stage 준비에서 reports directory 누락, 원래 worker adapter 복사 누락, 실패한 자체 unit 이름 재사용 충돌이 있었다. 첫 번째는 worker 전 경로 오류, 나머지는 raw NOT_CLEAN 기록으로 보존했다. 실제 모델 적재·forward 전에 발생했고 byte-exact adapter 복사와 새 고유 CPU unit으로 수정했다. CPU 정상 경로를 확인한 뒤 heavy를 한 번 실행했다. 안전 가드를 바꾸거나 서비스 reset/타 프로세스 종료로 우회하지 않았다. 상세 원래 상태와 사용량은 [COSTS](COSTS.json)에 있다.

마지막 출력과 각자의 앵커 사이 전체화면 RGB L1은 BASE_END18.6564, CORRECTED_END16.9864다. 서로 다른 앵커에 대한 진단이며 더 쉬운 앵커·배경 변화로도 작아질 수 있다. 이를 개체·동작 점수나 ENDPOINT_GAIN_ONLY의 근거로 쓰지 않는다.

## 결론과 다음 논의

이번 부분 교정 앵커는 종료32와 중간 얼굴 세부를 바꿨지만 원본 동작 개선은 확립하지 못했다. 교정 자체가 약했으므로 “앵커 충돌은 무관하다”는 원인 결론도 낼 수 없다. 앵커 충돌만으로 설명되지 않는 남은 문제는 보이는 부위의 시간별 대응, 머리·발의 관계와 배경 유지다. 다음 논의는 **부위 ID·시간 대응·가시성·신뢰도를 생성 모델에 전달하는 방법** 하나로 제한한다. 이번에는 구현·추가 생성하지 않았다.

한 개발 사례·한 seed이며 일반화나 새 알고리즘 성과가 아니다. A/B 실패·보류, C001 PARTIAL, C002 차량 TRADE_OFF/개 COARSE_CONTROL_ONLY, C003 NO_ESTABLISHED_GAIN을 보존한다. 추가 앵커·seed·prompt·모델 탐색 없이 종료한다. [검토물 전달](DELIVERY.json).
