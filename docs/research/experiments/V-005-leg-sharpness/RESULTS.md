# V-005 결과

빠른 발차기 구간(14–34프레임)의 R1 RAW는 기준 S2-s1보다 회색 픽셀 비율 평균이 0.1460→0.1398로 줄었지만, 경계 Laplacian 분산도 297.48→250.41로 줄었다. 이 조합만으로 다리가 더 선명해졌다고 판정하지 않는다. R3-s1은 15개 앵커로 생성했고 R3-s1/s2의 같은 구간 회색 비율 평균은 각각 0.1196/0.1308, 경계 분산은 292.91/307.88이었다. 이 값 역시 품질 판정을 대신하지 않는다. 사용자 검토에서는 실제 RAW의 발차기·다리 경계·Lab 크기를 먼저 비교해야 한다.

품질은 **HUMAN_REVIEW_PENDING**, 연속 지각 검수는 **temporal=UNVERIFIED**다. R1-a/b와 R3-s1/s2 총 4개 생성은 끝났으며 모든 출력의 SAM·CPU 지표와 비공개 SAMPLE 16개 검증을 완료했다. 출력 embedding 정체성 측정도 완료해 생성·측정의 기술 작업은 완료 상태다. 최종 전달·종료 검증은 별도 receipt로 확인한다.

## 생성과 비용

| 셀 | 실제 상태 | 생성 시간 | scheduler step / denoiser call | 비고 |
|---|---|---:|---:|---|
| R1-a | RAN | 81.614초 | 2 / 2 | 요청 σ=0.35 |
| R1-b | RAN | 82.124초 | 2 / 2 | 요청 σ=0.55 |
| R2-s1·s2 | NOT_SUPPORTED | 실행 안 함 | 0 / 0 | 동결 공식 IC-LoRA 경로는 distilled 전용 |
| R3-s1 | RAN | 136.592초 | 11 / 11 | 73프레임, CPU 측정 완료 |
| R3-s2 | RAN | 142.045초 | 11 / 11 | 73프레임, CPU 측정 완료 |

R1의 요청값 0.35와 0.55는 두 단계 모두 공식 격자의 같은 σ=0.421875로 대응했다. 각 단계에 1step만 남았고 두 RAW는 byte 동일하다. 따라서 서로 다른 유효 강도의 비교 결과가 아니다. 독립 실행 receipt는 각각 보존한다. 공통 RAW SHA256은 `60943c1b432bca2589b721b33d7d0930b91ddcfd6917d0f90df43be12bd2893d`다.

R1-a/b의 receipt peak RSS는 각각 약 42.28/42.24GiB, 관측 cgroup peak는 약 71.18/71.09GiB였다. R3-s1/s2 생성 supervisor는 COMPLETE, 반환값 0, 정상 종료 기록 true, NVRM 이벤트 0을 확인했다. 위 시간은 생성 receipt 시간이며 GPU 대기·SAM·CPU 처리·전송을 포함하지 않는다. 최종 자원 수치와 실행 장부는 [RUNS.json](RUNS.json)에 합산한다.

## 입력 유지와 앵커

18·22·26·30프레임의 신규 앵커 4장은 각각 첫 호출에서 수용됐으며 보정 호출은 없었다. native imagegen 실제 호출 4회, 기존 11장과 합쳐 수용 앵커는 15장이다. 기존 앵커와 확대 canny를 재사용했고 Lab·IG 배율을 다시 계산하거나 조정하지 않았다. 원본·후보·게이트 근거는 비공개로 보존하며 공개 기록은 [ANCHOR_LEDGER.json](ANCHOR_LEDGER.json), [ANCHOR_GATES.json](ANCHOR_GATES.json)에 둔다.

R2는 dev 가중치의 존재와 이번 고정 실행 경로의 지원 여부를 구분했다. 공식 동결 코드에서 Union IC-LoRA와 요구된 비축소 guided 경로의 조합을 확인하지 못했으므로 다운로드·생성을 하지 않았다. 근거는 [R2_SUPPORT.md](R2_SUPPORT.md)에 있다. 이로 인해 단계 축소가 번짐의 원인이라는 가설은 이번 실행에서 검증되지 않았다.

## 세 질문에 대한 현재 답

1. **다듬기 패스가 번짐을 해결했는가?** 회색 비율과 경계 분산 변화는 측정했지만 해결 판정은 사용자 검토에 남긴다. R1-a/b는 같은 실제 σ와 byte 동일 RAW이므로 강도 증가 효과를 비교한 독립 조건이 아니다.
2. **distilled 단계 축소가 원인인가?** R2는 NOT_SUPPORTED로 미실행이다. 비축소 모델의 실패로 해석할 수 없고 이 원인 가설도 시험되지 않았다.
3. **앵커를 2프레임 간격으로 늘리면 나아지는가?** 15개 앵커의 R3 두 seed를 생성·측정했다. 두 출력의 수치와 실제 영상을 제공하지만 선명도·동작·크기 보존의 품질 승자는 정하지 않는다.

## 검토 범위와 전달

R3-s1의 출력 SAM·POST·다리 및 동작 지표는 완료했다. 실제 개체 수 일치는 73/73, 확대 원본 대비 Lab 실루엣 IoU 평균은 0.5711, 20–34프레임 방향 대리 지표 일치는 12/15였다. 키프레임 SSIM은 승인 앵커 15시점을 모두 평가했다. R3-s2도 실제 개체 수 73/73, 앵커 SSIM 15시점을 측정했으며 확대 실루엣 IoU 평균 0.5851, 방향 대리 지표 일치 12/15였다. 이 IoU·방향 지표는 동작 성공 기준이 아니다. 출력 embedding은 앵커 15개와 출력 4×73프레임, 총 307개 항목을 측정했고 모든 출력의 Lab·IG coverage는 각각 73/73이었다. 이는 외형 참고값이며 사람의 정체성 판단을 대신하지 않는다. 최종 전달·종료 검증은 별도 receipt로 확인한다. 뷰어에서 RAW/POST를 구분하고 14–34프레임 반복·0.25/0.5배속·RAW 하체 확대·앵커 시트를 함께 확인한다. 최종 검토 폴더의 상대 위치는 `V005-review-20261106/index.html`이다. 실제 전달·무결성 확인은 별도 DELIVERY.json에 기록한다.

V-003·V-004 출력 12개와 V-005 출력 4개, 총 16개 비공개 SAMPLE은 경로·hash·입력 계보를 기록하고 사람 판정은 PENDING으로 둔다. 이 기록은 학습 실행이 아니다. 후속 학습·추가 생성·파라미터 탐색은 자동 시작하지 않는다.
