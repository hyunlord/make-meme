# V-005: 빠른 다리 동작과 다듬기

## 번짐에 대한 가설

빠르게 움직이는 다리는 짧은 시간에 위치와 가림 상태가 달라진다. 생성 모델이 그 위치를 충분히 확정하지 못하면 서로 다른 다리 위치를 섞은 듯한 윤곽이나 회색 잔상이 나올 수 있다. 이는 이번 문제를 설명하는 **가설**이며, 내부에서 실제로 픽셀 평균을 계산했다는 증거는 아니다. `guide` 앵커는 모델에 자세 정보를 더하는 조건이므로 해당 프레임의 생성 픽셀을 앵커로 덮어쓰거나 선명도를 보장하지 않는다.

distilled 모델의 적은 단계가 세부 복원에 불리할 가능성도 있지만 이번 결과만으로 원인을 확정할 수 없다. R2는 고정 공식 경로의 dev + Union IC-LoRA 결합 지원 조건이 충족되지 않아 NOT_SUPPORTED이며, 비축소 모델과의 실증 비교는 없다. 이는 모델 품질 실패가 아니라 고정 실행 경로의 지원 범위에 따른 미실행이다. R1 두 출력과 15개 앵커를 사용하는 R3 두 출력은 생성됐으며, 모든 출력의 SAM·CPU 지표를 측정했다. 출력 embedding 정체성 참고값도 모든 출력의 Lab·IG 73/73프레임에서 측정했다. 반투명 비율은 지정 밝기 범위의 회색 픽셀 비율이고 물리적 투명도 추정이 아니다. Laplacian 분산도 털 무늬·노이즈에 커질 수 있어 두 값으로 품질 우열을 정하지 않는다.

## σ에서 다시 시작하는 다듬기

R1은 이미 동작이 맞은 V-004 S2-s1 RAW를 VAE latent로 만든 뒤 일부 노이즈를 더하고 남은 denoise 단계만 실행한다. 기존 이미지·확대 canny·텍스트 조건은 유지한다. 공식 noiser는 `(1−σ)·입력 latent + σ·noise`로 섞고, 기존 조건 마스크를 적용한다. 일반적으로 작은 σ는 입력 형태를 더 남기고 큰 σ는 더 많이 바꿀 여지를 주지만, 선명도 개선과 동작·정체성 보존 사이의 관계를 미리 보장하지 않는다.

두 단계 모두 가장 가까운 기존 schedule 지점을 선택한다. 실제로 요청 **0.35와 0.55가 모두 0.421875**에 대응해 각 단계 1step, 실행당 합계 2step이었다. 단계 1은 입력 영상의 VAE latent, 단계 2는 그 다듬어진 결과의 공식 업샘플 latent에서 시작한다. R1-a와 R1-b RAW의 SHA256도 같으므로 이 둘은 서로 다른 실효 강도 비교가 아니다. 임의 sigma를 새로 넣어 차이를 만들지 않았다. 구체적 변경 경계와 실행 기록은 [RUNTIME_REFINE.md](RUNTIME_REFINE.md), [RUNS.json](RUNS.json)에 남긴다.

다리 국소 합성은 생성 결과와 별개의 CPU 파생본이다. 지정 영역·시간 ramp 안에서만 다듬은 픽셀을 사용하고 바깥은 S2-s1 RAW를 유지한다. 배경 POST도 별도로 보존한다. 최종 판단은 RAW 전체, 국소 합성, POST를 구분해 원본·Kling·S2-s1과 같은 시점에서 직접 재생한 뒤 내린다. 품질은 HUMAN_REVIEW_PENDING이다.
