# C-006: 점 궤적과 앵커 외형을 작은 모듈로 연결하기

이 실험은 “점의 시간별 이동을 명시적으로 주면, 윤곽 조건만으로 부족했던 내부 진행을 영상 모델이 더 잘 재현하는가?”를 묻는다. 아래 설명은 실제 C-006 구현을 따른다. 구현·미분 경로의 성립과 생성 품질의 개선은 별도 판정이다. 최종 생성 비교가 확정되기 전에는 학습 중간 상태나 CPU 검사를 연구 성과로 해석하지 않는다.

## 1. 그림으로 준 구조와, 명시적으로 준 점은 무엇이 다른가?

C-002와 C-003은 구조를 RGB 이미지로 그려 VACE의 기존 조건 인코더에 넣었다. 검은 선의 의미를 어디까지 활용할지는 기존 모델에 맡겼다. C-006에서는 점의 좌표와 가시성, 양끝 앵커에서 읽은 특징을 수치로 전달하고, 작은 학습 모듈이 이를 DiT 토큰에 더할 잔차로 바꾼다. 기존 VACE RGB 조건을 대체하거나 새로운 checkpoint 채널을 만드는 방법은 아니다.

점 번호 (k)는 추적기가 같은 점으로 연결한 식별자다. ‘왼쪽 앞발’, ‘무릎’ 같은 해부학적 부위 번호가 아니다. 화면 왼쪽에 있던 점이 움직여도 같은 번호를 유지할 수 있지만, 그 점이 실제로 같은 표면을 따라갔다는 보장은 별도다. `visible=True` 역시 추적기의 가시성 판단이며, 대응 정확도나 보정된 confidence 점수가 아니다.

`training_state.load_cache()`는 검토에서 제외한 궤적의 `valid`, `anchor_valid`, 패치를 비활성화한다. 원본 추적 NPZ는 수정하지 않는다. 제외되지 않은 점은 “정확함이 증명된 점”이 아니라 “이번 검토에서 제외하지 않은 점”이다. 데이터셋 마스크를 쓴 자기재현 조건은 MASK_GIVEN / DATASET_MASK_ASSISTED로 구분한다.

## 2. 외형 특징은 왜 양끝만 따로 인코딩하는가?

중간 정답 영상의 특징을 조건에 넣으면, 모델이 따라야 할 움직임을 알려 주는 것과 정답을 미리 보여 주는 것이 섞인다. 따라서 시작·종료 이미지를 각각 독립적으로 VAE 인코딩한다. 전체 정답 영상 latent에서 첫·마지막 시간 칸만 잘라 쓰는 방법은 시간 수용 영역을 통해 중간 프레임 정보가 섞일 위험이 있다.

`point_features.sample_anchor_patches()`의 입력은 두 번의 독립 인코딩을 쌓은 `[2,16,1,30,52]`다. 각 끝점에서 latent 한 칸 간격의 (3\times3) 이웃을 bilinear sampling하여 끝점마다 (16\times3\times3=144)개 값을 얻는다. 출력은 `[K,2,144]`다. 정규화 좌표는 이미지의 픽셀 중심 ((x+0.5)/W,(y+0.5)/H), `align_corners=False`를 사용한다. 유효하지 않은 앵커 패치는 0으로 만들고, 별도의 유효성 비트를 함께 준다. 0 패치가 실제 검은 외형이라는 뜻은 아니다.

## 3. 점 하나에서 303개 입력을 만드는 과정

점의 현재 좌표를 (q_{t,k}\in[0,1]^2), 두 앵커 패치를 (a_{0,k},a_{32,k})라 하자. 입력은 다음을 연결한다.

- 두 패치 288개와 양끝 앵커 유효성 비트 2개
- 현재 좌표 2개, 인접 프레임 이동량 2개
- 시작·종료점에 대한 좌표 차이 4개
- 영상 내 시간 (t/32) 1개, 가시성·유효성 비트 2개
- 실제 궤적 사용 여부 1개, 생성 잡음 수준 (sigma) 1개

합계는 303개다. 인접 이동량은 두 시점이 모두 유효하고 보일 때만 사용한다. `PointAnchorAdapter.forward()`는 `[33,K,303]`을 공유 MLP `303→192→192`에 통과시킨다. 활성 함수는 SiLU다. 점 번호별 embedding이나 별도 가중치는 없다. 점의 나열 순서가 바뀌어도 공간 합산 결과가 같도록 설계했다.

영상 시간 (t)와 잡음 수준 (sigma)는 다른 축이다. (t)는 33장 중 어느 장면인지 나타낸다. (sigma)는 그 영상 전체를 만드는 생성 과정이 얼마나 잡음 쪽에 있는지 나타낸다. 50 scheduler step은 50프레임이 아니다.

## 4. 점의 정보를 어느 토큰에 더하는가?

점마다 192차원 특징 (f_{t,k})를 얻어도, 그 정보를 화면 전체에 똑같이 더하면 위치 제어가 약해진다. 점 주변 토큰에 Gaussian 가중치로 전달한다.

\[
w_{t,k}(p)=v_{t,k}\exp\left[-\frac12\left(
\frac{(p_x-q_{t,k,x})^2}{b_{t,x}^2}+
\frac{(p_y-q_{t,k,y})^2}{b_{t,y}^2}\right)\right].
\]

여기서 (v)는 가시성·유효성·범위 검사를 통과한 gate다. 타원형 정규화 거리의 제곱이 9를 넘으면 가중치는 0이다. 폭 (b_t)는 **양끝 bbox 폭·높이를 선형 보간한 값의 8%**이며, 최소 폭은 각 축에서 토큰 한 칸이다. ON과 NULL 모두 같은 양끝 기반 폭을 사용한다. ON만 실제 중간 bbox를 사용하면 궤적뿐 아니라 전파 범위까지 달라지는 혼동이 생기므로, 실제 중간 bbox 값은 이 계산에 사용하지 않는다.

공간 특징은 다음과 같다.

\[
m_t(p)=\frac{\sum_k w_{t,k}(p)f_{t,k}}
{\max(1,\sum_k w_{t,k}(p))}.
\]

분모를 단순히 가중치 합으로 나누지 않는 이유는, 아주 먼 점의 작은 가중치가 정규화 때문에 다시 큰 신호가 되는 것을 막기 위해서다. 점이 겹치면 합산하고 정규화하므로, 점 개수가 늘었다는 이유만으로 잔차가 무제한 커지지 않는다. 이것이 의미적으로 다른 두 부위를 올바르게 구분해 준다는 보장은 없다.

## 5. 33프레임, 9개 시간 latent, 3510개 토큰

416×240 영상은 VAE에서 공간적으로 52×30, 시간적으로 9칸이 된다. DiT 공간 patchify 뒤에는 시간 9 × 높이 15 × 폭 26 = **3510개 토큰**이다. 순서는 T,H,W다.

점 조건은 명목상 시간 묶음 `[0]`, `[1..4]`, …, `[29..32]`를 사용한다. 먼저 각 원본 프레임에서 공간 splat을 계산하고, 묶음 안의 네 splat을 평균한다. 좌표를 먼저 평균하여 한 점으로 만드는 방식이 아니다. 예를 들어 점이 왼쪽에서 오른쪽으로 이동했다면, 두 위치의 support가 남는다. 평균 위치에만 가상의 점을 찍지 않는다. 다만 묶음 안의 세밀한 순서가 완전히 보존되는 것은 아니며, 이 명목상 대응이 VAE의 실제 시간 수용 영역과 정확히 일치한다는 주장도 하지 않는다.

최종 공통 특징은 `[1,3510,192]`다. 네 출력 projection이 각각 `192→1536`으로 바꾸어 DiT의 0-based **26,27,28,29번 블록 직전**에 더한다. `wan_adapter_forward.adapted_forward()`가 한 model call에서 특징을 한 번 만들고 네 블록에서 재사용한다. 전체 학습 파라미터는 **1,275,072개**다.

## 6. BASE, ON, NULL이 분리하는 효과

BASE는 adapter를 실제로 우회한다. 가중치를 0으로 만들고 모듈은 계속 실행하는 조건과 다르다. ON은 실제 중간 궤적·가시성·유효성을 사용하고 motion bit가 1이다.

NULL은 두 끝점으로 만든 경로만 사용하며 motion bit가 0이다.

\[
q^{null}_{t,k}=(1-t/32)q_{0,k}+(t/32)q_{32,k}.
\]

`make_null()`은 실제 중간 좌표, 가시성, 유효성, bbox를 읽지 않는다. 양끝이 모두 유효하면 선형 보간한다. 한 끝점만 유효하면 그 관측 위치를 정확히 반복하는 fallback을 쓰고, 둘 다 무효하면 gate를 끈다. 양끝 패치와 앵커 유효성은 endpoint 정보로 유지한다.

BASE↔ON은 학습 모듈과 실제 궤적을 추가한 전체 효과, BASE↔NULL은 endpoint 특징을 쓰는 학습 모듈 자체의 효과, ON↔NULL은 실제 중간 궤적의 추가 유용성을 본다. NULL도 움직이는 조건일 수 있다. 또 motion bit, 중간 visibility와 속도 정보도 함께 달라지므로 ‘좌표 한 요소만의 순수 인과효과’는 아니다.

## 7. Flow Matching에서 무엇을 학습하는가?

깨끗한 정답 영상 latent를 (z_0), Gaussian 잡음을 (epsilon)이라 하면 개념적인 경로와 목표 속도는 다음과 같다.

\[
z_\sigma=(1-\sigma)z_0+\sigma\epsilon,
\qquad u^*=\epsilon-z_0.
\]

실제 코드는 scheduler의 `add_noise()`와 `training_target()`을 호출한다. 임의의 다른 확산 목표를 추가하지 않는다. (z_0)는 학습 정답·잡음 구성에 쓰이며, 중간 정답 외형 특징을 adapter 입력으로 전달하는 용도가 아니다.

`training_state.balanced_loss()`는 채널 평균 제곱오차를 먼저 구하고, 객체와 배경 각각의 면적으로 나눈 두 평균을 **더한다**.

\[
\mathcal L=\frac{\sum M\,\|u_\theta-u^*\|^2}{\sum M}
+\frac{\sum(1-M)\,\|u_\theta-u^*\|^2}{\sum(1-M)}.
\]

두 항을 다시 2로 나눈 평균은 아니다. 이 loss용 영역 마스크 (M)는 VACE의 생성 여부 마스크 (G)와 다르다. 별도 pose·contact·identity loss는 없다. 따라서 loss 감소만으로 발 접촉이나 개체 정체성이 좋아졌다고 해석할 수 없다.

학습 중 NULL은 확률 25%로 선택한다. text dropout 10%의 실제 구현은 positive text embedding을 **고정 negative prompt embedding으로 대체**하는 것이다. 빈 문자열이나 0 tensor로 바꾸는 뜻이 아니다. CFG의 negative branch에서도 adapter가 사용되는 실행 조건을 고려한 선택이다.

## 8. backbone을 동결했는데 왜 backward가 필요한가?

동결은 backbone의 가중치를 업데이트하지 않는다는 뜻이다. adapter가 출력에 미친 영향을 계산하려면, 잔차가 들어간 뒤의 블록과 head를 통해 미분이 흘러야 한다. 그 구간까지 `no_grad`로 감싸면 adapter 학습도 끊긴다.

`adapted_forward()`는 처음 26개 블록과 기존 VACE hint 계산을 gradient 없이 수행한다. 마지막 네 블록과 head는 고정 가중치를 유지하면서 입력에 대한 미분을 전달한다. 학습 시 마지막 블록들은 activation checkpointing을 사용한다. 이 방식은 저장 activation을 줄이는 대신 backward 때 재계산 비용이 생긴다.

MLP는 일반적인 비영 초기화이고, 네 출력 projection만 0으로 시작한다. 첫 forward에서 잔차는 0이다. 첫 backward에서는 출력 projection에 gradient가 생기지만, 그 뒤로 전달하는 projection 가중치가 아직 0이므로 MLP gradient는 0일 수 있으며 이것이 예상 동작이다. 첫 optimizer update 후 projection이 바뀌면 두 번째 backward에서 MLP에도 gradient가 전달된다. projection은 bias가 없어 모든 점 gate가 꺼진 공간에 학습된 전역 bias가 생기지 않는다.

master parameter와 optimizer는 FP32, backbone은 기존 BF16 경로를 사용한다. trainable parameter가 130만 개보다 적어도 큰 동결 backbone의 forward, 후반부 backward, VAE 조건 캐시, 추적, 영상 생성과 검토 비용은 남는다. ‘작은 모듈’과 ‘전체 작업이 저렴함’은 같은 말이 아니다.

## 9. 현재 검증과 실제 출력 해석을 구분하기

CPU 검사는 초기 잔차 0과 우회, 점 순서 불변성, gate, 중간 정보를 오염시켜도 변하지 않는 NULL, ON/NULL 공통 kernel 폭, endpoint 패치 sampling, 시간별 support, 자기 retargeting 항등성, 첫·두 번째 gradient 전달을 확인한다. 이는 실제 생성 품질 검사가 아니다.

실제 학습은 256 update, 256 forward/backward로 완료됐다. 1,275,072개 adapter parameter는 최종 저장본에서도 모두 FP32·finite다. 최초 native↔bypass, native↔zero-adapter의 최대 절댓값 차이는 모두 0이었다. 후반 블록 26/27/28/29 및 head 입력의 gradient norm은 각각 약 0.01721 / 0.01020 / 0.00811 / 0.00710 / 0.00546으로 관측됐다. 첫 update에서 MLP gradient는 모두 0, 두 번째에는 네 MLP parameter 모두 0보다 컸다. 동결 파라미터의 version·표본 불변 검사와 checkpoint·optimizer readback이 통과했고, 재로딩 전후 예측의 최대 절댓값 차이는 0이었다. 이는 실제 미분·저장 경로의 증거이며 영상 품질 판정은 아니다.

고정 validation noise와 세 sigma에서 얻은 한 번의 속도 예측 오차는 다음과 같이 감소했다. checkpoint는 이 표나 test 영상의 외관으로 사후 선택하지 않고, 사전 고정한 마지막 완료 update 256을 사용했다.

| Validation 영상 | sigma | 초기 loss | update 256 loss |
|---|---:|---:|---:|
| elephant | 0.952381 | 0.918046 | 0.388782 |
| elephant | 0.833333 | 0.398955 | 0.238235 |
| elephant | 0.555556 | 0.261918 | 0.226518 |
| goat | 0.952381 | 0.876236 | 0.312970 |
| goat | 0.833333 | 0.329888 | 0.226491 |
| goat | 0.555556 | 0.286008 | 0.262788 |

이 여섯 probe는 정답 latent에 정해진 잡음을 섞은 지점에서의 one-step 오차다. 50-step 생성은 이전 예측으로 다음 상태를 만드는 연쇄 과정이며 CFG도 사용한다. 따라서 여섯 오차가 모두 낮아져도 생성 과정의 오차 누적·분포 이동이나 외관 손상을 배제할 수 없다. 실제 horsejump-low ON의 예비 검토에서는 넓은 붉은 잔상 문제가 보고됐다. loss 개선을 영상 개선으로 치환할 수 없다는 실제 반례 후보이며, 이 현상의 원인을 하나로 단정하지 않는다.

주 평가 두 사례의 전체33장·같은 인덱스 정적 검토에서 **NO_ESTABLISHED_GAIN**으로 판정했다. horsejump-low와 lucia 모두 ON과 NULL이 BASE보다 보호 장면·외관에서 회귀했고, ON이 두 대조군보다 원본 내부 진행을 더 잘 따랐다는 근거는 확립되지 않았다. horsejump-low ON의 넓은 붉은 잔상은 validation loss 감소와 실제 생성 회귀가 양립하는 사례다. 움직임·정체성·배경을 합쳐 성공으로 올리지 않으며, 기본 채택하지 않는다.

이 판정은 실제 생성 프레임 검토에 근거하지만 연속 지각 검토의 대체물이 아니다. temporal=UNVERIFIED다. 선택적 cross-ID dog도 NO_ESTABLISHED_GAIN이다. ON/NULL에서 얼굴 주변의 녹회색 잔상·블록 파편과 붉은 잔디 손상이 나타났고, 일부 16~28번에서는 NULL의 파편이 더 많아 보여도 ON이 BASE보다 낫다는 근거는 없다. 이 진단은 코·눈 3점의 HEAD_ONLY 조건이므로 다리 제어 효과를 판단하지 않는다. source24의 흐림과 기존 종료 앵커의 자세 충돌도 해석 한계로 남는다. 추가 학습·설정 탐색·새 모델 실행은 자동 시작하지 않는다.

## 10. 자기재현에서 개체 교체로 바로 일반화할 수 없는 이유

이번 주 평가는 학습하지 않은 영상에서 원본 양끝 앵커를 사용한 자기재현이다. 외형과 궤적이 같은 객체에서 왔으므로 서로 맞추기 쉬운 조건이다. 다른 개체로 편집된 앵커를 사용하면 원본 체형·가림·자세와 충돌할 수 있다.

선택적인 개 사례의 endpoint retargeting은 양끝 bbox 비율의 대각 행렬 (B_0,B_{32})를 사용하는 고정 2D 근사다.

\[
\tilde q_t=(1-t/32)\{a_0+B_0(q_t-q_0)\}
+(t/32)\{a_{32}+B_{32}(q_t-q_{32})\}.
\]

같은 끝점과 단위 비율이면 원래 궤적이 복원되는지 CPU로 확인한다. 그러나 이 항등성은 개체 교체 성공의 증거가 아니다. 회전·3D·관절 대응·가림 복원은 해결하지 않는다. 해당 진단이 실행되지 않으면 자기재현 결과만으로 외형 전이를 주장하지 않는다.

416×240, 작은 개발 분할, 단일 학습 예산과 제한된 test 영상에서 일반화 성능·정확한 관절 제어·접촉 정답·원본 외형 누수 제거를 결론낼 수 없다. 33프레임은 독립된 실험 33개가 아니다. ON이 나빠져도 ‘점 대응 연구 전체가 실패’한 것이 아니라 이번 추적 품질·표현·연결·학습량의 조합에서 이득이 입증되지 않은 것이다.

## 이해 확인

**Q. 점 번호 7이 모든 영상에서 같은 앞발인가?**  
A. 아니다. 번호는 해당 영상의 선택·추적 순서다. 공유 MLP는 번호별 embedding을 사용하지 않는다.

**Q. NULL의 점은 화면에 정지해 있는가?**  
A. 반드시 그렇지 않다. 두 끝점 사이를 이동한다. 실제 중간 움직임 대신 endpoint에서만 만든 경로라는 뜻이다.

**Q. 첫 backward에서 MLP gradient가 0이면 실패인가?**  
A. 이 초기화에서는 예상 동작이다. 출력 projection의 첫 gradient와 update 뒤 MLP gradient를 구분해서 확인해야 한다.

**Q. loss가 낮아지고 ON과 NULL tensor hash가 다르면 움직임 개선인가?**  
A. 아니다. 각각 최적화와 입력 차이에 대한 증거다. 실제 생성 결과에서 관측 가능한 동작이 두 대조군보다 나아졌는지를 따로 확인해야 한다.

**Q. 9개 시간 latent에 33개 점 시점을 평균하면 네 프레임의 순서가 그대로 남는가?**  
A. 아니다. 각 위치의 support는 남겨도 묶음 내부 순서는 일부 잃는다. 단순 평균 좌표보다 나은 정보 보존 의도와, 완전한 시간 대응 보장은 구분해야 한다.
