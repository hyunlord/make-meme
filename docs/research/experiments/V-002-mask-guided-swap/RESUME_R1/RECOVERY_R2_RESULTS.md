# V-002 복구 개정 2 진행 결과

M1 원본 영상은 Mac 전송 후 SHA256 일치를 확인했다. 기존 73프레임 출력(976.877초)을 재사용했고, 출력 SAM은 45.114초에 정상 완료했다. CPU 측정과 9시점 진단 시트를 완료했다. 실제 개 2마리 검출73/73, Lab/IG 평균 실루엣 IoU0.558980, 중심 궤적 거리1.98437%/0.703166%(화면 가로), 반대 최근접 대응 proxy0, Lab/IG 높이비1.50331, 마스크 밖 원본 RGB MAE0.969674, 배경 연속 변화/원본 비율1.85150이다. 이 값들은 사용자 품질 판정을 대신하지 않는다. 새 M1 영상 생성은 하지 않았다.

M2의 이전 시도는 재부팅 뒤 worker와 완료 출력이 없으며 마지막22step/45call이다. 미완료 기록을 보존하고 사용자 승인 1회 재시작을 실행했다. M3는 그 뒤 순차 실행하도록 배치했으나, 두 번째 연결 상실 뒤 현재 실행 여부는 UNKNOWN이다. 14B는 자동 선택하지 않으며 이번 복구에서 14B와 LTX canny를 실행하지 않는다.

실루엣 IoU는 사용자의 E1 동작 불일치 판정과 부합하지 않아 단독 동작 비교·자동 선택 지표로 신뢰도가 낮다. 설명용 값만 유지한다. 모든 새 출력의 품질은 HUMAN_REVIEW_PENDING, 연속 지각 검수는 UNVERIFIED다. 이전 RESULTS/RUNS는 관측 상실 시점의 역사 기록이며 현재 복구 상태는 이 문서와 RECOVERY_R2_RUNS.json을 기준으로 한다.

## 복구 실행 중 두 번째 관측 상실

M1 전달·검증 후 M2 재실행과 M3 순차 배치를 Spark tmux에서 시작했고, 별도 Spark 후처리 배치는 두 생성의 COMPLETE 영수증을 기다리도록 설정했다. M2는8 scheduler step/17 model_fn call까지 확인한 뒤, 2026-11-04T19:46:14Z의 제한시간 SSH 재확인이 timeout으로 끝났다. 이후 Tailscale offline을 관측했고 기존 SSH 호스트명에 대한 로컬 네트워크 이름 조회도 실패했다.

원격 배치의 현재 진행·완료·종료·새 부팅 여부는 미확인이다. M2를 다시 실행하거나 호스트를 재부팅하지 않는다. M3와 후처리는 마지막 확인 당시 대기 중이었으므로 이후 실행 여부도 접근 복구 전까지 UNKNOWN이다. 14B/LTX 호출은 배치에 포함하지 않았다. M1 실제 영상과 측정·시트의 Mac 전달은 이 연결 상실 전에 완료됐다.

2026-11-04T19:58:30Z 재확인도 SSH timeout이었다. 접근 불가로 이번 복구를 완결하지 못했다. 원격 tmux·worker 종료는 미확인이고, 이미 승인된 Spark 내부 배치의 이후 상태를 추정하지 않는다. 다음 접근 시 기존 worker·영수증·출력을 먼저 확인해야 하며, M2 재시작 1회 예산은 이미 사용했다. 로컬 검토물에는 실제 전달된 M1만 신규 영상으로 포함한다.
