# B-027 이후 제안 하나 — 대상 외형 주입과 원본 문맥 보존의 분리

상태: **PROPOSED / NOT_RUN / 추가 실행 승인 아님**. B-027의6개 raw를 모두 검토한 뒤 선택했다. B-026은 선택적 대기이고 더 유리한 개인 사진을 요구하지 않는다.

## 관측에서 선택한 병목

동물 두 참조는 source 외형을 남겼고, 차량은 색/몰딩·박스형 인상만 일부 바뀌며 정확한 target 형태는 미입증이다. 사람은 target 의상 반영이 있어 참조 전체가 무시된 것은 아니지만 팔/치마 배치와 형상 손상이 남았다. 또한 일부 조건은 대상 밖에 큰 그래픽·서명을 추가했다. 따라서 현재 prefix 조건이 있다는 사실만으로 대상 외형과 보호 문맥이 원하는 방식으로 분리되지는 않는다. 작은 참조·가림·도메인 차이가 섞여 있어 이 메커니즘을 확정 원인으로 주장하지 않는다.

## 다음 검증 가능한 방법 가설 하나

**명시적인 masked-video context branch와 대상 ID 주입을 분리한 공식 VideoPainter 경로가, 현재 SCAIL replacement보다 source 외형 잔존과 비편집 영역 추가 생성을 줄일 수 있는가?**

이는 새 모델 설치 자체를 성과로 삼자는 제안이 아니다. 공개 코드와 weights 제공이 확인된 하나의 기존 방법을 비교 대상으로 삼아, source에서 보존할 문맥과 새 대상 외형을 별도 경로로 주는 설계의 실제 효용을 검증하자는 가설이다. VideoAnydoor의 미공개 구현을 있다고 가정하거나 세 모델을 동시에 설치하지 않는다.

다음에 승인된다면 현재 고정한 공개 과제·target track·두 참조와 사전 사건을 보존하고, 공식 지원 계약에 따른 한정 비교를 사전 등록한다. 같은 edited GT가 없으므로 target 특징·source 사건·보호 영역·형상·전체 비용을 계속 따로 본다. native 해상도/길이/시간축 계약이 다르면 이를 명시하며 임의 warp나 유리한 프레임 선택으로 맞추지 않는다. 기존 SCAIL raw는 재생성하지 않는다.

이 비교는 backbone과 조건 구조가 함께 달라지는 **방법 묶음 비교**이며 context branch 하나의 순수 인과효과가 아니다. 단일 Spark에서의 dtype·attention·전체 로딩/peak·필수 다운로드·실행시간이 아직 미확인이다. 공식 파일 목록 존재를 GB10 실행PASS로 대체하지 않으며 실제 승인 전에 자원 상한과 지원 계약을 확인해야 한다. 그 경로가 부적합하면 임의 fallback이나 큰 서버로 바꾸지 않는다.

수용 근거는 (1) source 객체의 외형을 남기지 않고 target의 여러 특징을 반영, (2) 참조 정지 복사 대신 source 사건 유지, (3) 노출된 보호 배경에 불필요한 객체/문자 추가 감소를 함께 보는 것이다. 가림·시간 품질·비용을 별도 보존하고, 하나만 나아진 결과는 PARTIAL이다. 이번에는 이 방법의 설치·추론·학습을 실행하거나 예약하지 않았다.

근거 문헌·고정 revision·실제 제공 범위는 [학습 문서](../../lessons/B-027-public-reference-robustness.md)의 VideoPainter 항목을 따른다. 추가 SCAIL offset/CFG/seed/update sweep이나 개인 사진 의존으로 돌아가지 않는다.
