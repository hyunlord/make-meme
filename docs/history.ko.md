# make-meme 개발 기록: 방향성, 작업 내용, 히스토리

이 문서는 `feature/swap-mcp` 브랜치에서 진행한 작업의 배경, 결정 사항, 실험 결과, 현재 상태를 정리한 기록이다.
다음 작업자(사람이든 에이전트든)가 맥락을 이어받을 수 있도록 "왜 이렇게 됐는지"를 중심으로 적는다.

## 1. 목표와 요구사항

- 영상(파일, YouTube·TikTok·Instagram·Threads 링크, 또는 텍스트 검색)과 사진(사람 또는 동물), 프롬프트를 받아 **영상 속 인물을 바꾼 밈 영상**을 만드는 **오픈소스 MCP 서버**(Apache-2.0).
- 출발점이 된 예시는 A2O LITE의 "니온(NEON)" MV다. 두 멤버를 사용자의 강아지 두 마리(이탈리안 그레이하운드, 블랙 래브라도)로 바꿔 **영상 하나**로 만드는 것이 목표다.
- 사용자 요구:
  - **무료**: 유료 API를 쓰지 않는다. 단, 각자 GPU를 연결하거나 API를 연결하는 선택지는 열어 둔다.
  - **동물 지원**과 **높은 품질**.
  - 사진을 정리하지 않고 한꺼번에 넣어도(단체 사진 포함) 알아서 분류해야 한다.
  - 밈이 실제로 쓰는 구간과 길이를 스스로 판단해야 한다(숏폼이 MV의 어느 부분을 얼마나 쓰는지).
  - 여러 밈 "방식"(레시피·스타일)을 계속 추가할 수 있는 구조여야 한다.
  - Claude Code에서 직접 지시할 때뿐 아니라, **다른 사람이 MCP로 써도** 제대로 동작해야 한다.
  - 궁극적으로 **어떤 컴퓨터에서든 빠르고 품질 높게** 만들 수 있어야 한다.
- 품질 목표의 단계(사용자 지시 순서):
  1. 얼굴이 완벽하게 따라갈 것
  2. 몸까지 바뀔 것
  3. 1과 2가 되면 지시에 따라 모션도 바꿀 것

## 2. 아키텍처 요약

```
MCP 도구 (FastMCP, src/make_meme/server.py, tools_*.py)
  plan_meme ──> MemePlan(JSON) ──> render_meme ──> 작업 큐 ──> 영상 1개
     │                                   │
     ├ 구간 분석 (analyze_meme_usage)     ├ 엔진: swap(MoCha) | paste(얼굴 붙이기) | animate(Wan2.2-Animate)
     ├ 컷 분할, 출연자 매칭               ├ 컷별 처리 → 원본 해상도·fps로 이어 붙이기 → 원본 오디오
     ├ 9:16 리프레이밍                    └ 캐시: 끝난 컷은 다시 렌더할 때 재사용
     ├ 사진 정리 (organize_photos: SAM3 + DINOv2)
     └ 스타일 팩 선택 (builtin_styles/*.yaml)

ComfyUI (로컬 또는 원격 GPU 서버, 토큰 프록시)
  레시피 = workflow.json + recipe.yaml (builtin_recipes/*)
  컴패니언 노드 팩 make_meme_nodes (RoPE 패치, 통계, 추적 라벨, 캐시 비우기, 통합 메모리 안전장치)
```

- **레시피**: 생성 방식 하나를 데이터로 정의한다(모델, 노드, 프로필별 설정, 프리셋, 제약).
  - 예: `mocha_swap`, `wan_animate_replace`, `qwen_character`, `sam3_detect`, `sam3_track`
- **스타일 팩**: 밈 하나를 어떻게 만들지 정의한다.
  - 엔진, 마스크, 참조 사진, 프롬프트, 캐릭터 디자인 프롬프트, 레시피 값(`recipe_values`)을 담는다.
  - 예: `pet_head_paste`, `pet_idol_fur`, `pet_idol_outfit`, `pet_full_body`, `pet_head_swap`, `person_swap`
- **계획 → 렌더**: 클라이언트 LLM이 도구를 순서대로 엮지 않아도 같은 품질 로직을 타도록 선언적 계획(MemePlan)을 중심에 둔다.
- **하드웨어 프로필**: `mps`(Apple Silicon), `cuda`, `cuda_lowvram`, `cpu`.
  - 통합 메모리 GPU(DGX Spark / GB10)는 `cuda`로 판정하고 전용 안전장치를 켠다.

## 3. 타임라인

### 1단계: 기반 (10-17 새벽)
- 프로젝트 골격, 미디어 수집(yt-dlp, 자체 Threads 파서, 검색), 자산 저장소, 작업 큐, ffmpeg 후처리를 만들었다.
- ComfyUI 클라이언트, 레시피 시스템, SAM 3.1 검출, **MoCha**(Wan2.1 기반 인물 교체) 레시피를 붙였다.
  - Mac(MPS)에서 돌리려고 MoCha RoPE를 실수 연산으로 바꾸는 패치를 넣었다.
- 보안 수정: SSRF 차단, 로컬 경로 보호, 원격 GPU용 토큰 프록시.
- `analyze_meme_usage`: 숏폼 오디오를 MV와 상호상관으로 맞춰 밈이 쓰는 구간을 찾는다.
  - 니온은 MV의 앞부분 약 18초.
- `reframe_video`(9:16 자동 팬), `suggest_mappings`(어느 사진이 어느 인물이 될지 정함).

### 2단계: 계획→렌더 구조와 사진 정리 (10-17 오전)
- 사용자 피드백 1: "너무 짧고 늦게 시작한다", "옷을 억지로 입힌 느낌", "사진을 막 넣어도 분류되나?"
- `organize_photos`: 단체 사진 분리, DINOv2 임베딩으로 같은 개체 묶기, 대상별 참조 사진 2장 고르기.
- MemePlan과 스타일 팩, 여러 컷 처리, 성능 측정(perf.jsonl), T5 미리 인코딩.
- 버그 수정: 컷 결합 SAR 불일치, 두 번째 인물 생성이 첫 번째를 덮어쓰는 문제(원본 기준 독립 생성 후 변화량 마스크로 합성).

### 3단계: MoCha 결과 평가 → 방향 전환 (10-17 오전~오후)
- Mac 밤샘 렌더(288×512, Q4, 4스텝)에 대한 사용자 평가: **"아무것도 안 비슷해"**.
  - 원인 1: 포즈 가이드가 없음
  - 원인 2: 첫 프레임 마스크만 사용
  - 원인 3: 청크마다 독립 생성
  - 원인 4: Mac 메모리 한계
- **`pet_head_paste`**(생성 모델 없이 추적한 강아지 얼굴 컷아웃을 붙이는 방식)를 만들었다.
  - 원본 1080p 그대로, Mac에서 수 분 만에 끝난다.
  - SAM3 텍스트 추적으로 재검출하고, 추적 결과를 멤버에 연결하고, One-Euro로 떨림을 줄였다.
  - 프레임 단위로 정확하게 잘라 오디오 싱크를 맞추고, 짧은 컷 몽타주 분할을 바로잡았다.
- 사용자 평가: "왜 머리만 따라가? 몸도 바뀌어야 한다." → 생성형으로 다시 간다.

### 4단계: Wan2.2-Animate와 DGX Spark (10-17 오후~밤)
- **`wan_animate_replace`** 레시피: ViTPose로 뽑은 포즈와 얼굴, 배경 영상, 마스크로 안무를 그대로 따라간다.
- **캐릭터 디자인** 단계: `qwen_character`(Qwen-Image-Edit-2511)로 사진 속 강아지를 "두 발로 선 캐릭터" 기준 이미지로 먼저 바꾼다.
  - 엎드린 사진을 그대로 쓰면 모델이 몸을 지어낸다.
- DGX Spark(GB10, 128GB 통합 메모리)를 원격 엔진으로 붙였다.
  - 별도 ComfyUI를 두고, Tailscale 내부 토큰 프록시로 연결한다.
- **Spark가 두 번 꺼짐.** 원인은 GPU 순간 전력 급등으로 인한 과전류 보호다(로그 없이 전원이 꺼짐).
  - 사용자가 `nvidia-smi -lgc 300,2100`으로 클럭을 제한하고 스왑을 끈 뒤 안정됐다.
  - 코드에 넣은 안전장치:
    - 통합 메모리용 실행 옵션(`--disable-mmap --reserve-vram 20 --disable-pinned-memory --disable-cuda-malloc`)
    - 페이지 캐시 비우기, 실행 전 여유 메모리 점검(`min_free_gb`), 6GB 이하로 떨어지면 작업을 끊는 감시 스레드
- GB10(sm_121) 대응: cuDNN 어텐션이 계획을 못 세우는 shape에서만 cuDNN 없이 다시 시도한다.

### 5단계: 품질 개선 반복 (10-17 밤 ~ 10-18)

| 문제 | 원인 | 해결 |
|---|---|---|
| 머리만 생성하는 스타일 실패 | 이 모델은 머리 부분만 바꾸는 구조가 아님 | 스타일 제거. 전신을 바꾸면 머리도 따라간다 |
| 검은 사람 실루엣이 됨 | 정확한 실루엣 마스크를 주면 그 구멍만 채운다 | 공식 전처리처럼 32px **블록 마스크** 사용 |
| 긴 컷이 망가짐(검은 실루엣, 블록 흔적) | 77프레임을 넘으면 looping 모드로 바뀌고 배경·마스크 조건이 깨진다 | ≤77프레임 **창 단위 생성** + 5프레임 크로스페이드 |
| 원본 인물이 남음 | 매칭된 멤버만 교체 | **화면의 모든 사람 교체**(남는 인물은 남은 캐스트로, 조각은 가까운 인물로) |
| 그레이하운드가 두꺼움 | 설명이 "회색 동물"뿐이라 품종을 몰랐다 | 품종·체형 설명을 넣어 다시 디자인하고, 사람 근육·눈을 금지어로 추가 |
| 사람 손이 나옴 | 포즈에 손가락 키포인트를 그린다 | 털 스타일은 `hand_stick_width: 0` |
| 래브라도 얼굴이 사람 얼굴 | 멤버 얼굴 크롭이 표정을 구동한다 | `face_strength: 0` |
| 머리카락이 남거나 계단 모양 경계 | 사람 마스크에 날리는 머리카락이 빠짐, 블록 단위로 붙여 넣음 | 실루엣과 변화량 기준 합성, 머리카락은 깨끗한 배경으로 덮기 |
| 검은 블록(face 0 부작용) | 모델이 칠하지 않은 영역이 검은 채움으로 남음 | 배경 영상을 비울 때 **깨끗한 배경 판(시간축 중앙값)**으로 채움(검증 중) |
| 속도 | SDPA, CPU 포즈 추출, 모델 재적재 | torch 2.14 cu130 + **SageAttention**(GB10 검증 커밋) + GPU onnxruntime, 모델 상주, 생성 해상도를 원본으로 제한 |

### 측정치 (DGX Spark, 클럭 2100MHz 제한)
- 니온 18초 전체:
  - 480p, 4스텝: 2시간 10분(개선 전)
  - 608×1072, 6스텝: **1시간 42분**(개선 후)
- 같은 컷 비교: 3초 넓은 컷 1375초 → 601초, 0.5초 컷 512초 → 313초(SageAttention 등 적용 후)
- 캐릭터 디자인: 1장당 약 1분
- 메모리: 생성 중 최대 약 40~55GB(다른 서비스 포함 시스템 기준으로 가용 메모리가 33GB 이상 유지됨)

## 4. 현재 상태 (10-18 오후)
- 가장 좋은 결과: `pet_idol_fur` 고화질 18초.
  - 넓은 군무 컷은 강아지가 안무를 그대로 따라 춘다.
  - 클로즈업은 여전히 사람 같은 상체가 남는 경우가 있다.
- 지금 검증 중: `face_strength 0` + 깨끗한 배경 판으로 채우기. 개 얼굴을 유지하면서 검은 블록이 사라지는지 확인한다.
- 남은 문제:
  - 카메라 쪽으로 뻗는 큰 팔(흐릿한 전경)이 추적 마스크에 안 잡혀 사람 팔로 남는다.
  - 옷 입은 스타일의 그레이하운드가 파랗게 칠해진다("blue-grey"를 글자 그대로 해석).
  - 그레이하운드 클로즈업의 사람 같은 상체.
  - 포즈 리타깃: 체형은 좋아지지만 위치가 어긋나고 인물이 사라지는 경우가 있어 기본값은 꺼짐.
- 테스트 446개 통과(GPU 없이 도는 단위·통합 테스트).

## 5. 다음 방향
1. 검은 블록 해결을 확인하면 `pet_idol_fur` 고화질 18초를 다시 렌더한다.
2. 옷 입은 스타일: 디자인 설명 보정("blue-grey" → 회색 계열 표현) 후 렌더한다. 클로즈업의 사람 해부 구조 문제를 옷이 가려 줄 것으로 기대한다.
3. 전경의 큰 팔: 추적 해상도 상향 또는 "arm/hand" 추가 추적을 검토한다.
4. 3단계 목표: 지시에 따른 모션 변경. 다른 영상의 포즈를 가져오고 박자를 맞춰 Wan-Animate 애니메이션 모드로 생성한다.
5. "어디서나" 목표: API 엔진(fal/Replicate의 Wan-Animate)을 연결한다. 마스크·다중 인물 지원과 가격을 먼저 확인해야 한다.

## 6. 운영 메모
- **원격 GPU 서버**: `docs/engine-setup.md`의 "Option C"를 따른다(설치, `comfy start`, 토큰 프록시, `COMFY_URL`/`COMFY_TOKEN`).
- **DGX Spark**: 재부팅할 때마다 sudo로 `swapoff -a`, `nvidia-smi -lgc 300,2100`을 다시 해야 한다. 안 하면 영상 생성 중 전원이 꺼질 수 있다.
- **SageAttention**: `make-meme install --sage`로 빌드한다. 서버에 있으면 레시피가 자동으로 `sageattn`을 쓴다.
- **렌더 캐시**: 컷별로 키가 붙고 파이프라인 버전이 들어간다. 마스크 방식처럼 결과가 바뀌는 변경을 하면 `ANIMATE_PIPELINE_VERSION`을 올린다.
- 사용자 사진과 개인 경로, 토큰은 저장소에 넣지 않는다.
